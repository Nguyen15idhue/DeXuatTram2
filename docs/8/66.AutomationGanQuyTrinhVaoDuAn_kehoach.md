## 0. Quyết định đã chốt với user (không đổi khi implement)

1. **Automation đầu tiên**: "Tự động gán công việc quy trình vào dự án". Khi **duyệt & đẩy lần đầu** 1 đề xuất sang 1Office (lúc đó 1Office tự sinh công việc quy trình tương ứng) → tìm quy trình theo **mã đề xuất** → tự gán vào dự án. Có thêm **nút chạy tay** từng đề xuất.
2. **Retry/timeout mặc định**: timeout tìm quy trình **60 giây**, thử **3 lần** (sửa được trên UI sau).
3. **Dự án đích là 1 dự án cố định**, đổi được trên UI (mặc định mã `'2'` — "Đánh giá đầu tư hạ tầng trạm sạc", ID số `3`).
4. **Cấm dùng API token `process/update` để gán** (đã chứng minh làm rớt khối Liên quan, xem §1). Automation **bắt buộc đi đường session-web** `POST /apps/work-task-task/moveprocess` (giữ quan hệ, đã test thật thành công trên 1422 ngày 05/10/2026).
5. **Password tài khoản 1Office**: UI hiện `••••••`, response API **không bao giờ** chứa password thô (F12/Network không soi được); đổi pass = nhập mới đè lên, bỏ trống = giữ cũ. Lưu DB mã hóa AES-256-GCM (key từ env `AUTOMATION_KEY`), không ghi password vào log.

## 2. Luồng tổng thể kế hoạch

```
Duyệt & đẩy đề xuất lần đầu (PENDING → REVIEWING, push contact OK)
  → tạo work_automation_runs { status:'pending', proposal_code, contact_code }
Runner (tick 20s, reuse cronMatcher.js):
  pending + automation enabled
    → GET /api/work/process/gets?filters=[{"s": mã }] (token contact/work trong api_configs)
    → chưa thấy + chưa quá find_timeout_s (60s) → để lại, thử lại sau retry_interval_s
    → thấy root process:
        + đã ở đúng dự án → status 'skipped' (không tạo EDIT rác)
        + chưa → login session 1Office (giữ cookie, hết hạn login lại)
             → POST moveprocess { ID, project_id: <ID số>, parent_id: '' }
             → OK → 'success'; lỗi → retry tới retry_max (3) → 'failed' + notify ADMIN/SUPER
Nút "Chạy thủ công" (tab automation): nhập mã đề xuất → chạy ngay 1 lượt đồng bộ (tối đa 60s/3 lần), ghi run riêng (trigger='manual')
```
