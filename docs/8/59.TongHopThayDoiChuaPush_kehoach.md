## Phase 2 — Xác nhận hoàn thiện thông tin + tự động hủy quá hạn

**Mục đích (yêu cầu người dùng):** countdown chỉ hiện "Còn hạn" (không hiện "Quá hạn"); record cũ coi như đã hoàn thiện; thêm nút xác nhận (có undo + popup chống bấm nhầm) trong form view/edit; quá hạn chưa xác nhận → tự hủy với lý do "Chưa cập nhật đầy đủ thông tin"; sắp hết hạn → cảnh báo.

### 2.1. Database — migration `115-proposal-info-completed.sql` (đã chạy)
- `ALTER TABLE station_proposals ADD COLUMN info_completed_at DATETIME NULL` (NULL = chưa xác nhận), guard `information_schema` idempotent.
- Backfill: toàn bộ record hiện tại `= NOW()` → không báo quá hạn nữa.

### 2.2. Backend
- `proposalLifecycle.setInfoCompleted(id, completed, opts)`: chặn khi hết deadline/status ngoài countdown (kể cả CANCELLED → nút tự ẩn); confirm `SET NOW()` + notify, reopen `SET NULL` (giữ deadline cũ) + log `info_completed`/`info_reopened`.
- Notify cả 2 hành động tới **chủ + cây cấp trên (`parent_id`, tới GĐKV/GĐTT) + ADMIN/SUPER_ADMIN**, trừ người thực hiện. Type mới `INFO_COMPLETED` (teal), `INFO_REOPENED` (vàng) trong `notificationService.STATUS_TITLES`.
- `transition()` xóa cờ khi reset deadline (giữ cờ khi chung mốc PENDING↔REVIEWING); resubmit `myProposalService` cũng xóa cờ (mốc mới → xác nhận lại).
- List admin/my (`adminProposalService`, `myProposalService`) trả thêm `info_completed_at`.
- Worker `processDeadlines`: `WHERE info_completed_at IS NULL`; quá hạn (kể cả guest) → `transition CANCELLED` lý do chuẩn (idempotent tự nhiên, lỗi → `auto_failed`); sắp hết hạn giữ nguyên cảnh báo `SUPPLEMENT_EXPIRING` theo `warn_hours`.
- API mới (kèm Swagger): `POST /admin/proposals/:id/confirm-info|reopen-info` (`requireUserManager` + `denyOutsideBranch`), `POST /my-proposals/:id/confirm-info|reopen-info` (chỉ chủ). Controller 2 bên.

### 2.3. Frontend
- `DeadlineCountdown.jsx`: thêm prop `completedAt`; đã xác nhận **hoặc** quá hạn → ẩn hẳn; chỉ còn "Còn hạn". 3 chỗ dùng (`AdminProposalsPage`, `MyProposalsPage`, `RecordDetailPopup`) truyền thêm prop.
- `RecordDetailPopup.jsx`: khối nút khi còn `supplement_deadline_at` + status countdown + `allowEdit` (record hủy tự ẩn nút) — "Xác nhận đã đủ thông tin" / nhãn xanh + "Mở lại để bổ sung", đều qua `ConfirmDialog`; xong `setRecord(res.data)` + toast + refresh chuông + `onSaved`.
- `NotificationBell.jsx`: màu 2 type mới. `ProposalActivityPopup.jsx`: nhãn 6 action mới (`info_completed`, `info_reopened`, `deadline_*`...).
- `services/api.js`: 4 helper confirm/reopen (admin + my).

**Mục đích:** upload giữ tên tự do; lúc **lưu** chuẩn hóa thành VD `LK_HNO_0006_Ảnh vị trí dự kiến lắp đặt trụ sạc_1.png`.

### 4.1. Thiết kế
- File vật lý (tên random) không động; chỉ đổi `files.original_name` (tên hiển thị/download) **và** tên nhúng trong `custom_data` (tên FE đang hiển thị) → lưu xong thấy tên mới ngay.
- Giữ đuôi ext gốc (kể cả `.PNG` hoa) — bỏ đuôi thì tải về Windows không mở được. Thiếu mã → fallback `DX{id}`. STT = vị trí trong field hiện tại: idempotent (lưu lại không đổi), xóa file giữa thì đánh lại STT.
- `fileService.renameProposalFiles({dynamicData, fieldDefs, maDeXuat, connection})`: duyệt field `type=file/source=json`, sanitize label (bỏ `/\`, control char, gọn khoảng trắng).
- Hook sau post-formula ở 4 luồng: `proposalService.createProposal` + `createGuestProposal`, `adminProposalService` + `myProposalService.updateProposal` (chỉ ghi lại `custom_data` khi có đổi tên).
