## 0. Trả lời câu hỏi: nút Hủy là undo hay dừng giữa chừng? + mô tả dòng chưa import

**Chốt: Hủy = dừng giữa chừng (stop). Những dòng đã import thành công trước thời điểm hủy được GIỮ LẠI, không xóa. Đồng thời job PHẢI ghi nhận và mô tả rõ những dòng CHƯA được import để người dùng biết.**

Lý do chọn stop (không undo):

1. Kế hoạch này đổi ngữ nghĩa import từ all-or-nothing sang **partial** (mỗi dòng autocommit riêng — xem Phần 3). Khi đã partial thì không còn transaction tổng để rollback; "undo" đồng nghĩa với **xóa mềm/xóa cứng hàng loạt bản ghi đã tạo** — nguy hiểm: mã đề xuất `SEQ` đã cấp không thu hồi được, log activity `source:'import'` đã ghi sẽ mồ côi, trạm/đề xuất có thể đã bị người khác sửa sau khi import.
2. Luồng đúng khi hủy: worker kiểm tra cờ `cancelled` mỗi N dòng (5–10) rồi dừng → job chuyển `status='cancelled'`, giữ nguyên `imported/failed` tới thời điểm dừng → popup chi tiết + 2 nút xuất vẫn hoạt động bình thường trên tập đã xử lý.
3. Nếu sau này cần "undo thật", làm tính năng riêng **"Hoàn tác job import"** (xóa các `success_ids`, chỉ cho phép khi record chưa bị sửa sau import + chỉ SUPER_ADMIN) — ngoài phạm vi kế hoạch này, ghi vào mục 7 (việc tương lai).

**Yêu cầu bắt buộc khi hủy (bổ sung theo yêu cầu user 01/10/2026):**

1. Worker khi dừng phải chốt tập **dòng chưa import** = các dòng trong file có thứ tự sau dòng dừng (chưa từng được xử lý) → lưu vào `pending_rows` (`[{rowNumber, data:{...ô gốc}}]`, chung cap 2000 dòng với `failed_rows`) + đếm `pending`.
2. Popup chi tiết job `cancelled` hiển thị khối riêng **"Dòng chưa được import (do hủy)"**: tổng số dòng + bảng (Dòng file | Tóm tắt dữ liệu) + câu diễn giải ví dụ: *"Job dừng ở dòng 312/500 — 188 dòng từ 313 đến 500 chưa được import."*
3. Nút **Xuất bản ghi thất bại** khi job `cancelled` xuất GỘP cả 2 tập: dòng lỗi (`Lý do` = lỗi cụ thể) + dòng chưa import (`Lý do` = `"Chưa xử lý do hủy job"`), vẫn giữ nguyên header/cột file gốc → người dùng import bù đúng phần thiếu mà không trùng phần đã ăn.
4. Notification khi hủy ghi rõ 3 số: đã import / lỗi / chưa import (ví dụ: *"Đã hủy import: 300 đã tạo, 5 lỗi, 195 chưa xử lý — xem tab Excel"*).

Ranh giới khái niệm (để implement + test không nhầm):

| Tập dòng | Định nghĩa | Lưu ở | Xuất ở |
|---|---|---|---|
| Đã import (`imported`) | INSERT thành công | `success_ids` | Nút Xuất thành công |
| Lỗi (`failed`) | Đã xử lý nhưng validate/INSERT lỗi | `failed_rows` + `error` từng dòng | Nút Xuất thất bại (`Lý do` = lỗi) |
| Chưa import (`pending`) | Chưa từng xử lý do hủy giữa chừng (chỉ có khi `cancelled`) | `pending_rows` (không có `error`, chỉ `rowNumber + data`) | Gộp vào file Xuất thất bại (`Lý do` = `"Chưa xử lý do hủy job"`) |

```sql
CREATE TABLE IF NOT EXISTS import_jobs (
  id VARCHAR(64) PRIMARY KEY,
  entity VARCHAR(50) NOT NULL,
  action VARCHAR(50) NOT NULL DEFAULT 'import',
  status ENUM('queued','processing','done','partial','failed','cancelled') DEFAULT 'queued',
  total INT NOT NULL DEFAULT 0,
  done INT NOT NULL DEFAULT 0,
  imported INT NOT NULL DEFAULT 0,
  failed INT NOT NULL DEFAULT 0,
  pending INT NOT NULL DEFAULT 0,
  params JSON,
  file_name VARCHAR(255),
  columns JSON,
  failed_rows LONGTEXT,
  failed_truncated TINYINT(1) NOT NULL DEFAULT 0,
  pending_rows LONGTEXT,
  pending_truncated TINYINT(1) NOT NULL DEFAULT 0,
  success_ids JSON,
  warn_details JSON,
  error_message TEXT,
  created_by INT,
  started_at TIMESTAMP NULL,
  finished_at TIMESTAMP NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_import_status (status, created_at),
  KEY idx_import_user (created_by, created_at),
  FOREIGN KEY (created_by) REFERENCES users(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```
