## 0. Kết quả khảo sát code (căn cứ ra quyết định)

- Widget schema 2 nhánh: system `{metric,title,chart,size,order}` (metric ∈ 22 `METRIC_REGISTRY`) và builder `{dataset,dimension,metric,agg,filters[≤10],sort,limit≤200,chart,size,title,order}` (`reportService.parseWidgets:560-600`, `reportBuilderService.validateWidget:134-181`). Mặc định chart `table` (system) / `bar` (builder), size `md`.
- 17 widget seed `pipeline` **toàn system widget**, không dataset (`database/151`, orders 1–17: funnel/KPI/bar/pie/table/line).
- RBAC: mọi GET báo cáo `requireReportViewer` (SUPER/ADMIN/MKT/SALES); mọi ghi config `requireReportConfigurator` (chỉ SUPER_ADMIN) (`routes/adminReports.js`, 12 endpoint). Scope: SALES theo nhánh đệ quy, GĐTT theo phòng ban, GĐKV theo `assigned_user_id`, SALES khác `1=0`; MKT theo `created_by`; station suy từ proposal (`reportService:63-175`).
- Durations (`getLead360`): mốc **đầu tiên** (earliest), `dayDiff` null khi thiếu/âm; fallback chỉ `created_at`/`assigned_at`; stage **không bao giờ hạ** (`recomputeStage`, `LEAD_STAGE_RANKS`); ON dính luôn khi đã `ACTIVE`. Aggregate toàn scope: lead→proposal dùng `MIN(created_at)`/journey, proposal→station tính từng cặp (`datasetAverageDuration:236-252`).
- **Lỗi phát hiện khi khảo sát (phải sửa trước, thuộc Task BE-0)**: `reportBuilderService.validateWidget` đọc `reportService.SIZE_WHITELIST` nhưng `reportService.js` chỉ export `CHART_WHITELIST` → nhánh check size ném TypeError thay vì 400.
- Rủi ro Excel: `exportDynamic` **không LIMIT** (xuất full WHERE); scope stations/users dựa hoàn toàn vào route guard; export proposals của SALES chỉ 1 cấp cha-con (lệch với nhánh đệ quy của báo cáo). Báo cáo Excel mới phải dùng scope báo cáo + giới hạn dòng.

## 1. API contract (thống nhất trước khi code song song)

### 1.1. Schema cấu hình `report_config_v2`

```json
{
  "version": 2,
  "widgets": [
    { "id": "w1", "kind": "system|builder|detail", "metric": "lead_funnel",
      "dataset": "leads", "dimension": "stage", "measure": "id", "agg": "count",
      "filters": [{ "key": "stage", "op": "=", "value": "NEW" }],
      "sort": "value_desc", "limit": 20,
      "chart": "bar|line|pie|table|kpi|funnel|echarts_bar|dwell",
      "title": "...", "layout": { "x": 0, "y": 0, "w": 6, "h": 4 } }
  ]
}
```

- Giữ nguyên mọi field widget v1 (tương thích migrator §5); thêm `id` ổn định (nanoid client), `kind` (`detail` = bảng chi tiết Lead→ON), `layout` RGL `{x,y,w,h}` thay `size/order` (migrator đổi `size→w`, `order→y`).
- Giới hạn giữ nguyên v1: widget ≤50, filter ≤10 (`key≤60/op∈7/value≤100`), limit 1–200, sort ∈4, title ≤120, chart/size whitelist (mở thêm `echarts_bar`, `dwell`).
- Response chuẩn `{ success, data, message }`; lỗi validate 400 `{ success:false, message, details? }`; preview rỗng trả `rows: []` + `empty: true` (FE hiện EmptyState, không toast lỗi).

### 1.2. Endpoint mới (prefix `/api/admin/reports`, RBAC cũ giữ nguyên)

| Endpoint | Quyền | Request | Response |
|---|---|---|---|
| `GET /lead-details` | Viewer | filter chung (8 filter hiện có) + `page/limit≤200` | `{ items[], pagination }`; mỗi item: lead_code, full_name, created_at, assignee (id/label), department, cskh_count, tvbh outcome, proposals[{code,status}], station{name,status}, on_at, total_days + `durations{5 chặng}` |
| `GET /stage-durations` | Viewer | filter chung | `{ stages: [{ key, min, avg, max, n }] }` — công thức = `datasetAverageDuration` mở rộng 5 chặng, mốc earliest, null khi thiếu |
| `GET /builder/datasets` | Viewer (giữ) | — | catalog + dimension mới: `leads.assigned_department/sales_outcome/has_proposal/has_station` |
| `POST /export/excel` | Viewer | `{ widget } \| { detail: true, filters }` | `.xlsx` (exceljs BE, tối đa 5000 dòng, đúng scope báo cáo) |
| `PUT /config` | Configurator (giữ) | `{ version: 2, widgets[] }` | layout đã lưu; từ chối `version` lạ (400, để migration tương lai) |

- Dataset/dimension/metric/agg định nghĩa duy nhất trong `reportBuilderService.DATASETS` (không schema thứ hai ở FE); FE catalog chỉ hiển thị label.
- Quy tắc nghiệp vụ đóng băng: durations lấy mốc earliest; stage không hạ; lead nhiều proposal tính proposal sớm nhất, proposal→station tính từng cặp; thiếu log → `null` (hiện "—"), không ước lượng; `ON` = `stations.status='ACTIVE'` duy nhất.
