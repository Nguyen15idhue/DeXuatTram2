# 65. Webhook trạm + Mã trạm chờ + Tạo trạm khi ký thành công — kế hoạch

> Ngày lập: 03/10/2026. Trạng thái: **đã implement + test xong toàn bộ (chưa push GitHub theo yêu cầu)**.
> Nguồn yêu cầu: user.

## 0. Quyết định đã chốt với user (không đổi khi implement)

1. **Không lập bảng mã trạm riêng.** Dùng cột `pending_station_code UNIQUE` trên đề xuất (= đăng ký mã chờ) + hàm check chung UNION cả 2 nguồn. Giữ `SEQ()` làm bộ cấp số (nguyên tử); **cấm** formula tự "check DB rồi sinh số tiếp theo" (mất nguyên tử, race trùng số).
2. **Mapping field trạm theo key trực tiếp** (phương án A): mình đặt tên key trước, báo 1Office gửi đúng tên đó. Không dựng bảng mapping/UI.
3. **Hủy/từ chối giữ nguyên mã chờ** (không thu hồi, SEQ không lùi).
4. Vào `CONTRACT_SIGNED` → **tạo trạm ngay** + **1 thông báo gộp** "đề xuất {mã} ký hợp đồng thành công và tạo trạm {tên/mã}". Tạo trạm lỗi → vẫn báo ký thành công kèm lỗi tạo trạm.
5. Webhook trạm nhận **mọi trạng thái**, chỉ validate giá trị + log đầy đủ.

## 1. Chi tiết kế hoạch (luồng tổng thể)

```
Đề xuất vào PRINCIPLE_APPROVED (duyệt chủ trương)
  → sinh mã trạm chờ (SEQ theo ma_tinh, VD E.HN.0042), lưu pending_station_code, log
  → (hủy/từ chối sau đó: giữ mã)

Đề xuất vào CONTRACT_SIGNED (webhook 1Office)
  → tạo ngay trạm DEPLOYING: ma_tram = mã chờ, tọa độ/địa chỉ đề xuất
  → 1 notify gộp (ký thành công + tạo trạm)
  → tự đẩy đề xuất sang 1Office + đặt contact bên đó sang "Đang triển khai" (Bước 6)
  → ẩn đề xuất khỏi map (trùng trạm)

1Office chạy quy trình → POST /api/webhooks/oneoffice/station-update
  { event_id, ma_tram, status?, fields: {trien_khai_ha_tang, so_luong_tru, ...}, note? }
  → update trạm + log station_activity_logs (đổi trạng thái / đổi trường / nội dung 1Office gửi sang)
```
