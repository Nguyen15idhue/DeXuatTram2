## 2. Phạm vi

### 2.1. Trong phạm vi (MVP)

- Editor 3 vùng: Toolbar1 / Canvas (RGL 12 cột) / Panel phải 2 tab dọc.
- Nhiều báo cáo = tab.
- Widget types: **KPI, cột, cột ngang, đường, tròn/donut, bảng, bảng chi tiết Lead→ON, văn bản/tiêu đề, control-ngày, control-danh mục**.
- Filter cấp dashboard (control widget) lọc mọi chart cùng dataset.
- **Fit-to-width (cập nhật 2026-10-11)**: canvas tự **co/giãn đúng tỉ lệ** để xem trọn nội dung trong bề rộng khả dụng — **KHÔNG dùng thanh cuộn ngang** để xem nội dung. Chỉ widget **bảng/dữ liệu** được cuộn **bên trong ô** (table scroll nội bộ). Chart luôn vẽ lại theo đúng tỉ lệ đã cấu hình.
- **View mode chiếm toàn chiều rộng** từ sidebar đến hết màn hình (không panel cấu hình) và scale để lấp đầy bề rộng; **Edit mode** tự thu nhỏ vừa khung (vì có panel) — không phải kéo ngang để chỉnh.
- Panel Cấu hình chia **3 mini-tab** (tham khảo Looker Studio): **Thiết lập / Kiểu / Loại biểu đồ** (xem §3.7).
- Lưu/khôi phục, Undo/Redo, dirty + cảnh báo rời trang, chống race, retry.
- View mode sạch (ẩn công cụ chỉnh sửa, control filter vẫn hoạt động).
- Phân quyền: xem = LEAD_ROLES, sửa/lưu = SUPER_ADMIN (BE đã enforce).
- Responsive desktop/tablet/mobile.
- Xuất CSV/Excel (giữ endpoint `POST /export/excel` + `POST /builder/export`).

> Mockup tham chiếu: `docs/8/77.DashboardEditorLooker_mockup.html` (đã áp dụng fit-to-width, view full width, config 3 mini-tab).

### 2.2. Ngoài phạm vi (đợt sau)

- Pivot table, area chart, stacked bar đầy đủ, multiselect filter (`IN`).
- Dataset 1Office (`oneoffice_mirror`, `automation_runs`).
- Hình ảnh/logo widget, gửi email định kỳ, xuất PDF/PNG.

## 3. Kiến trúc

### 3.1. Bố cục 3 vùng

```
┌───────────────────────────────────────────────────────────────────────┐
│ ReportToolbar: [báo cáo][tên][trạng thái] │ Undo Redo │ [+ Thêm ▾] │ Lưu │ Xem │
├──────────────────────────────────────────────────────┬────────────────┤
│ ReportTabs: [Báo cáo tổng hợp] [Báo cáo X] [+]        │  (tab trong edit)│
│                                                      │                │
│                  REPORT CANVAS (RGL)                 │ PANEL PHẢI     │
│   KPI  KPI  KPI  KPI                                 │ ┌──┬─────────┐ │
│   Chart lớn            Chart nhỏ                     │ │Dữ│ nội dung│ │
│   Bảng dữ liệu         Control filters               │ │liệu        │ │
│                                                      │ │Cấu│        │ │
│                                                      │ │hình        │ │
└──────────────────────────────────────────────────────┴────────────────┘
```

- **Edit mode**: canvas + panel song song; canvas **fit** theo bề rộng còn lại (thu nhỏ, không cuộn ngang).
- **View mode**: ẩn Toolbar1 (chỉ còn toggle Xem/Chỉnh sửa), ẩn panel → canvas **full width** từ sidebar đến hết màn hình, scale để lấp đầy.

### 3.2. Cây component FE

```
ReportEditorPage (frame: load danh sách báo cáo + báo cáo đang mở)
├── ReportTabs (danh sách báo cáo = tab; thêm/đổi tên/xóa)
├── ReportToolbar (chỉ ở edit): undo/redo, thêm widget, lưu, toggle xem/sửa, trạng thái
├── ReportEditorLayout (view + edit dùng chung canvas)
│   ├── ReportCanvas (RGL; editable toggle + FitScaler — scale nội dung theo bề rộng)
│   │   └── WidgetRenderer (chọn theo type)
│   │       ├── KpiWidget / BarWidget / BarHWidget / LineWidget / PieWidget
│   │       ├── TableWidget / DetailTableWidget / TextWidget
│   │       └── ControlWidget (date/select — cấp dashboard)
│   ├── ReportDataSourcePanel (tab dọc A — luôn có)
│   └── ReportConfigPanel (tab dọc B — 3 mini-tab: Thiết lập / Kiểu / Loại biểu đồ)
└── ReportPanelTabs (thanh 2 tab dọc, chỉ ở edit)
```

- Tách state ra `hooks/useReportEditor.js`: `{ reports, activeReport, widgets, page, selectedId, viewMode, dirty, saveState, history, undo, redo, addWidget, updateWidget, deleteWidget, duplicateWidget, setLayout }`.
- Không để 1 component khổng lồ; canvas/toolbar/data panel/config panel/renderer/state tách riêng.

### 3.3. Model widget v2

```json
{
  "id": "w1", "type": "chart", "title": "...",
  "dataSourceId": "leads",
  "dataConfig": { "dimension": "stage", "metric": "id", "agg": "count",
                  "filters": [{ "key": "stage", "op": "=", "value": "NEW" }],
                  "sort": "value_desc", "limit": 20 },
  "visualConfig": {
    "chartType": "bar", "showTitle": true, "palette": "default",
    "showLegend": true, "legendPosition": "right", "legendAlign": "center", "legendMaxRows": 3,
    "showLabels": false, "labelValue": "value",
    "innerRadius": 0, "groupOthers": false,
    "numberFormat": "plain", "fontSize": 12,
    "background": "#ffffff", "borderColor": "#e5e7eb", "borderRadius": 8
  },
  "layout": { "x": 0, "y": 0, "w": 6, "h": 4 },
  "version": 2
}
```

- `visualConfig` mức **vừa phải** (không quá phức tạp): chỉ bật tùy chọn **áp dụng cho `chartType`** đang chọn (vd `innerRadius`/`groupOthers` chỉ cho pie/donut; `showLabels` bỏ với pie/donut/kpi). Không hỗ trợ HTML/JS tùy ý.
- `type`: `chart | table | kpi | text | control | detail`.
- Control widget: `{ id, type:"control", controlType:"dateRange"|"select", dataSourceId, field, defaultValue, title, layout, version }`.
- Text widget: `{ id, type:"text", title, visualConfig:{ text, align, fontSize }, layout, version }`.
- Detail widget: `{ id, type:"detail", title, layout, version }` (bảng Lead→ON, dùng `/lead-details`).
- Cấu hình trang: `page = { title, columns: 12, rowHeight }`.

### 3.4. Filter cấp dashboard (control widget)

- Control là 1 widget trên canvas. Runtime state `controlValues = { [controlId]: value }`.
- Khi query 1 chart: nếu `control.dataSourceId === chart.dataSourceId` và chart không phải control/text → **merge** thành filter:
  - `dateRange`: `field >= from`, `field <= to`.
  - `select`: `field = value`.
- Merge ở `utils/reportModel.js` trước khi gọi `POST /builder/preview` (backend đã nhận `filters[]`, **không cần API mới**).
- Options của control: FE gọi `POST /builder/preview` group theo `field` (distinct) để lấy danh sách; hoặc lấy từ datalist nếu có. Không tạo endpoint mới.

### 3.5. Nguồn dữ liệu (adapter)

- Tab "Nguồn dữ liệu" đọc `GET /builder/datasets` → 6 dataset; **ẩn** `oneoffice_mirror`, `automation_runs` → còn 4: `leads`, `proposals`, `stations`, `journey_events`.
- Field = `dimensions` (chiều phân tích) + `metrics` (chỉ số). Search + nhóm theo loại.
- Chọn field → set vào chart đang chọn (dimension hoặc metric).

### 3.6. Lưu trữ (nhiều báo cáo)

- Bảng `report_builder_dashboards(id, name, layout_json, created_by, updated_by)`.
- `layout_json = { version:2, page:{...}, widgets:[...] }`.
- Dùng API CRUD sẵn có: `GET/POST /builder/dashboards`, `GET/PUT/DELETE /builder/dashboards/:id` — nâng validator sang v2.
- Migrate 17 widget seed `report_dashboard_configs('pipeline')` → 1 báo cáo "Báo cáo tổng hợp" (script một lần, đọc-only rồi seed nếu bảng trống).

### 3.7. Panel Cấu hình — 3 mini-tab (tham khảo Looker Studio)

Trong tab dọc **Cấu hình**, khi chọn 1 thành phần, hiển thị **3 mini-tab ngang** (không quá phức tạp, chỉ lấy phần phù hợp):

**1. Thiết lập** (data):
- Nguồn dữ liệu (dataset).
- Phương diện (dimension).
- Chỉ số (metric).
- Phép gộp (agg).
- Hiển thị: số hàng trên cùng (`limit`).
- Sắp xếp.
- Bộ lọc (điều kiện riêng của widget).

**2. Kiểu** (style):
- Tên biểu đồ + hiện tiêu đề.
- Bảng màu.
- Tùy chọn **theo loại**: pie/donut → bán kính trong, nhóm phần còn lại thành "Khác"; cột/đường → hiện nhãn dữ liệu.
- Chú giải: hiển thị, vị trí, căn chỉnh, số dòng tối đa.
- Định dạng số.
- Nền & đường viền (màu nền, màu/độ đậm/bán kính/kiểu đường viền) — mức tối giản.

**3. Loại biểu đồ**:
- Gallery chọn nhanh `chartType` (Cột / Cột ngang / Đường / Tròn / Donut / Bảng / Số lớn).

Quy tắc:
- Chọn widget khác → reset mini-tab về **Thiết lập**; không mất thay đổi chưa lưu (state giữ ở `useReportEditor`).
- Tùy chọn **không áp dụng cho loại biểu đồ** đang chọn thì **ẩn/vô hiệu**.
- Widget `control`/`text`/`detail` không hiện tab Kiểu/Loại biểu đồ (chỉ Thiết lập tương ứng).
- Khi **không chọn** widget → Cấu hình hiển thị **cấu hình trang** (tên báo cáo, số cột, chiều cao hàng, khôi phục bố cục).
