## Giai đoạn A — Tự tạo job push khi lưu đề xuất

### A.1. Các bước triển khai

**Bước A1 — Config công tắc**
- `backend/src/services/proposalLifecycle.js`: thêm `AUTO_PUSH_ON_UPDATE_KEY = 'auto_push_on_update'`, `exports.isAutoPushOnUpdateEnabled()` (đọc key, **mặc định `true` khi key vắng**), `exports.saveAutoPushOnUpdate(v)` — pattern `getExtendLimits/saveExtendLimits` (:536-563).
- `database/141-auto-push-on-update.sql`: idempotent
  ```sql
  INSERT INTO proposal_lifecycle_configs (`key`, `value`) VALUES ('auto_push_on_update', '1')
  ON DUPLICATE KEY UPDATE `updated_at` = CURRENT_TIMESTAMP;
  ```
- `backend/src/controllers/lifecycleConfigController.js`: GET trả thêm `auto_push_on_update`, PUT nhận field này (validate boolean).
- `backend/src/routes/lifecycleConfig.js`: cập nhật Swagger `@swagger` cho GET/PUT.

**Bước A2 — Helper `autoPushOnUpdate(id, actorId)`**
- Đặt trong `proposalLifecycle.js`, cạnh `autoSyncOnApproved` (:288), lazy `require('./syncService')`.
- Logic (thứ tự):
  1. `isAutoPushOnUpdateEnabled()` = false → `{skipped: 'config_off'}`.
  2. `apiConfigService.getDefaultPushConfig()` null → `{queued: false, reason: 'Chưa có cấu hình API 1Office đang hoạt động'}`.
  3. Load proposal — chưa có `contact_1office_code` → `{skipped: 'not_linked'}`.
  4. Status **`CANCELLED`** → `{skipped: 'status_excluded'}`. **Tất cả status còn lại OK** (kể cả `REJECTED` — quyết định #3).
  5. `syncService.pushTo1Office([id], cfg.id, actorId, { allowAllStatuses: true })` — tận dụng dedup + missing-user-field check.
  6. Fail (thiếu trường người phụ trách…) → `logActivity action='sync_push', source='system_auto'` (mô-típ `autoSyncOnApproved` :302-308) → `{queued: false, reason}`.
  7. **Không bao giờ throw** — mọi lỗi nuốt + trả reason (không chặn lưu).

**Bước A3 — Hook vào 2 service lưu**
- `adminProposalService.updateProposal` (:154) — ở **cuối hàm**, sau lần ghi `custom_data` cuối cùng (post-formula + rename file): gọi `autoPushOnUpdate(id, opts.actorId)` → `return { autoPush }` (hàm hiện trả `undefined`).

**Bước A4 — Controller trả `autoPush`**
- `adminProposalController.update` (:187): nhận kết quả service, response thêm `autoPush`.
- `myProposalController.update` (:43): tương tự.

**Bước A5 — FE toast + poll job**
- Extract `pollSyncJobs` (`AdminProposalsPage.jsx:773`) → `frontend/src/utils/syncJobPoll.js` (dùng chung cho A5 + G).
- `RecordDetailPopup.handleSave` (:426-442): đọc `res.autoPush`:
  - `queued` → toast `"Cập nhật thành công — đã tạo lệnh đồng bộ sang 1Office"` (+ warnings nếu có) → poll job → toast kết quả (mô-típ `AdminProposalsPage:358-371`, có nút xem Audit Log khi fail).

**Bước A6 — Toggle UI**

## Giai đoạn C — Fix đồng bộ file (xóa + upload lại)
