## 1. Chi tiết kế hoạch (tổng quan)

### 1.1. Mục tiêu

1. Giữ nguyên thước đo chim bay (Haversine, offline, không quota).
2. Thêm chế độ **Ô tô**: quãng đường + thời gian lái xe gần nhất qua Geoapify Routing `mode=drive`, vẽ đường bám đường đè lên đường thẳng.
3. User chuyển qua lại bằng **toggle `Chim bay | Ô tô`** trên thanh đo, ở cả 2 nơi: trang `/map` (`MapView.jsx`) và modal fullscreen (`LocationMapModal.jsx`).
4. Không lộ `api_key` ra browser (proxy qua backend, tái dùng key geocode), có cache + rate limit để sống trong quota miễn phí **3000 req/ngày**.

### 1.2. Nguyên tắc

- Chim bay là fallback mặc định: chưa có 2 điểm, lỗi mạng, hết quota, không tìm được đường → luôn hiện số chim bay, không crash.
- Chỉ gọi routing khi: `mode='drive'` + `points >= 2`, trigger **mỗi click thêm điểm** (không gọi khi rê chuột / pan / zoom).
- Không đổi schema DB trừ khi cần bảng cache (ưu tiên cache memory + tái dùng `geocode_cache` pattern, không migration nếu tránh được).
- Mọi bước xong phải: FE build PASS, backend khởi động không lỗi, verify thủ công Definition of Done (AGENTS.md mục 17), không phá ruler cũ / legend / filter / snap.

### 1.3. Ước tính quota (cơ sở chốt thiết kế)

- Hiện trạng (DB 30/09/2026: 35 users, 105 đề xuất/30 ngày ≈ 3.5/ngày, peak import 58/ngày, `geocode_cache` 398 dòng): reverse geocode TB ~10–20 req/ngày, peak ~60–120 req/ngày → chiếm <5% quota.
- Tile mặc định OSM/Esri miễn phí → 0 req Geoapify. **Cấm chuyển tile provider sang `geoapify`** (15 tile/lần mở map → hết quota trong vài phút).
- Routing theo thiết kế click-trigger: đo 4 điểm ≈ 3–4 req. Kịch bản nhẹ (5 người × 3 lần × 3 điểm) ~45 req/ngày (2%); trung bình (15 × 5 × 4) ~350 req/ngày (12%); nặng (35 × 10 × 5) ~1.900 req/ngày (63%) — vẫn qua nếu có cache.

## Bước 1 — Backend proxy `/api/routing/drive` (giữ key + cache + rate limit)

### Nội dung

- Tạo `backend/src/services/routingService.js`:
  - Đọc `api_key` từ `geocode_configs` (tái dùng key geocode, không thêm cột DB).
  - `round5(n)` (5 chữ số thập phân ~1m) cho cache key; `hashWaypoints(points)` = join `lat,lng` đã round.
  - Cache memory (`Map`, TTL 30 ngày, cap 2000 entries, sweep khi đầy) — key: hash, value: `{ distanceM, timeS, geometry }`. Ghi chú: nếu muốn persistent thì bước sau mới thêm migration bảng `route_cache`.
  - `getDriveRoute(points[])`: check cache → `https.get` Geoapify (`mode=drive`, `format=json`, timeout 8000, `User-Agent: StationManagement/1.0 (Routing)`) → parse `features[0]` → chuẩn hóa `{ distanceM, timeS, coordsLatLng[] }` (đảo GeoJSON `[lng,lat]` → `[lat,lng]` cho Leaflet) → set cache.
  - Validate: 2–25 điểm, lat ±90, lng ±180, tổng chiều dài URL < 7000 ký tự (vượt → 400 hướng dẫn chia nhỏ).
- Tạo `backend/src/routes/routing.js`: `GET /api/routing/drive?waypoints=lat,lng|lat,lng` (+ `POST` body `{points:[[lat,lng]]}` cho >10 điểm). Thêm `@swagger` JSDoc. Mount ở `app.js` (`/api/routing`).
- Thêm rate limit ở `middlewares/rateLimits.js`: `routingLimiter` 60 req/phút/user (giống geocode), key theo user id + IP.
- Lỗi trả 200 `{ success:true, data:{ found:false, reason } }` cho `NO_ROUTE`/`QUOTA`/`NO_KEY` (FE fallback chim bay, không toast đỏ), chỉ 400 cho input sai.

### Yêu cầu cần đạt

1. Key không xuất hiện trong response / log / FE bundle.
2. Cùng waypoints gọi 2 lần → lần 2 không sinh req ra Geoapify (hit cache).
3. Hết key / hết quota / không có đường → trả `found:false` có `reason`, HTTP vẫn 200.
4. Swagger `/api-docs` hiện endpoint mới.

- [ ] Gọi lại y hệt → backend log không gọi Geoapify lần 2 (cache hit).

- [ ] Gọi >60 lần/phút → 429, FE vẫn hiện chim bay.
