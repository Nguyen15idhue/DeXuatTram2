## 4. Kiến trúc

**DB (migration `111`, chỉ thêm — idempotent):**
- `document_templates`: `id, name, entity='station_proposals', model ENUM('TDT','NQ','LK'), file_id→files, mapping JSON, status, is_default, created_at, updated_at`.
- `document_constants`: `id, key, label, value, group_name, updated_at`.

**`mapping` JSON:**
```jsonc
{
  "tokens": {
    "lk_ten_phap_nhan": { "source": "field", "key": "lk_ten_phap_nhan" },
    "plan_tdt": { "source": "datalist", "listId": 12, "match": { "column": "loai_hinh", "value": "Tự đầu tư" }, "column": "so_luong_ke_hoach" },
    "so_van_ban": { "source": "const", "key": "so_van_ban" }
  },
  "loops": {
    "tdt_tru": { "source": "field", "table": "tdt_tru", "stt": true,
      "columns": { "loai_tru": "loai_tru", "so_luong": "so_luong", "don_gia": "don_gia", "thanh_tien": "thanh_tien" },
      "footers": [ { "id": "f1", "label": "Tổng cộng chi phí", "formula": "SUM(thanh_tien)" } ] },
    "luy_ke": { "source": "datalist", "listId": 12, "filter": [], "columns": { "loai_hinh": "loai_hinh", "so_luong": "so_luong_ke_hoach", "luy_ke": "luy_ke" } },
    "loai_tru_lk": { "source": "field", "table": "loai_tru_lk", "stt": true,
      "columns": { "loai_tru": "loai_tru", "so_luong": "so_luong", "don_gia": "gia_niem_yet", "thanh_tien": "thanh_tien" },
      "footers": [ { "id": "tmt", "label": "Tổng chi phí TMT", "formula": "SUM(thanh_tien)" } ] },
    "chi_phi_lk": { "source": "field", "table": "chi_phi_lk", "stt": true,
      "columns": { "loai_chi_phi": "loai_chi_phi", "so_tien": "so_tien" },
      "footers": [ { "id": "dt", "label": "Tổng chi phí đối tác", "formula": "SUM(so_tien)" } ] },
    "dia_diem": { "source": "fixed", "rows": [ { "dia_chi": "{address}", "link": "{link_de_xuat}" } ] }
  }
}
```
- Token trong Word dùng ngoặc nhọn docxtemplater (`{token}`, loop `{#loopKey}…{/loopKey}`), **single-run**. Script chuẩn hoá **chỉ merge các run cần thiết** để tạo placeholder hoàn chỉnh và **giữ nguyên `w:rPr`/formatting** của vùng text (không merge toàn bộ paragraph).
- Dòng footer cố định chứa token do engine sinh (`{tdt_tru_f1_label}`, `{tdt_tru_f1_value}`).
- Bảng "Danh sách địa điểm lắp đặt": **1 dòng cố định** (`dia_chi` ← `address`, `link` ← link maps); template NQ/LK giữ danh sách (nếu cần lặp sau thì chuyển sang loop `fixed`).
- Công thức footer dùng **đúng ngữ nghĩa** `frontend/src/utils/tableFooter.js` (SUM/AVG/MIN/MAX/COUNT của cột, `%`, số học, hàm IF/ROUND…), tính **server-side** trên cùng normalized rows.
- **Pipeline bất biến**: `template.docx` (trong `files`) → copy trong bộ nhớ → `doc.render(data)` → `generated.docx`. Cấm recreate paragraph/table, convert DOCX→HTML→DOCX, đổi style/khổ giấy/margin/width/merged-cell/header/footer/section/kích thước ảnh.
- **Loop bảng**: dùng cơ chế loop/table của **docxtemplater** nếu đáp ứng yêu cầu giữ nguyên cấu trúc; nếu không, dùng **helper OOXML có kiểm soát** để clone nguyên `w:tr` của dòng template (giữ `w:tc`, width, border, shading, alignment, vertical alignment, merged-cell, paragraph/run formatting). Tag `{#k}`/`{/k}` phải nằm trong **cùng 1 table row**; cấm loop lồng sai, loop cắt ngang 2 row. Tuyệt đối không recreate table/paragraph.
- **Vai trò mammoth + docx-preview**: DOCX XML là nguồn sự thật cho engine; mammoth chỉ dùng cho outline/preview HTML nhẹ; khung preview trực quan dùng **`docx-preview`** (render đúng khổ giấy/bảng/vị trí token, dynamic import, chunk riêng ~77KB). Mọi tương tác preview chỉ đổi `mapping` trong state, không sửa file docx.
- **Mapping metadata** (tương thích ngược): token `{..., "format": "text|number|date"}`; loop `{..., "render": {"empty": "hide|blank"}}`. Thiếu metadata → hành vi mặc định cũ.
- **Template integrity validation** (`POST validate` mở rộng): token hợp lệ; mỗi `{#loop}` có `{/loop}` tương ứng; loop nằm đúng 1 table row; không lồng sai; column mapping tồn tại; footer token tồn tại; cảnh báo duplicate token bất thường, token split-run, cấu trúc DOCX không hỗ trợ/file hỏng.
- **Bulk isolation**: mỗi proposal render từ snapshot dữ liệu riêng (object mới cho từng document); cấm mutable global state trong `documentService`. Trả `{success, generated, skipped, warnings: [{proposalId, reason}]}`.
- **QA bằng PDF**: `DOCX → PDF` bằng LibreOffice headless; kiểm tra số trang, tràn margin, lệch header/footer, text đè nhau, mất border/merged-cell/logo/chữ ký, trang trắng lạ. Có thể visual diff khi cần.

**API (BE):**
- `GET/POST /api/admin/documents/templates`, `GET/PUT/DELETE /api/admin/documents/templates/:id` (`requireSuperAdmin`) — upload docx qua `fileService`.
- `GET /api/admin/documents/templates/:id/tokens` — liệt kê token/loop phát hiện trong docx.
- `POST /api/admin/documents/templates/:id/validate` — token chưa bind, công thức footer sai, loop không cột.

- `POST /api/admin/proposals/reports` (`requireUserManager` ADMIN/SALES) — `{proposalIds, templateId?}` → 1 đề xuất: `.docx`; nhiều: `.zip` (mỗi đề xuất render theo mô hình của nó; gặp `NQ_LK` → bỏ qua + ghi log/warning).

**Frontend:**
- `pages/admin/AdminDocumentsPage.jsx` — danh sách template (model, file, mặc định, trạng thái) + upload/thay file + constants (tab/đoạn).
