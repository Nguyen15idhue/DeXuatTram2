## A. Cơ chế thực hiện (1 agent)

> Từ 2026-10-08: **chỉ một agent duy nhất (`build`) làm toàn bộ dự án** — không chia ORCH / W-A / W-B, không chạy song song nhiều session. HUMAN review ở các checkpoint C0–C6.

### A.1. Quy trình chạy & Issue loop

```text
USER (task)
   │
   ▼
agent chạy từng bước theo Dependency của bước
   ├─ tự test theo Checklist của bước
   └─ ghi Files đã sửa + Kết quả test vào file 70 (cùng phiên)
   │
   ▼
HUMAN review checkpoint C*n ── PASS ──► mở sprint kế
   │
  FAIL ──► Issue (ghi file 70) → fix → review lại → PASS
```

1. Đọc `AGENTS.md` + kế hoạch 68 + file 69 (và file 70 cho kết quả các bước trước) trước khi làm bước.
2. Chạy đúng thứ tự **Dependency**; không mở sprint khi checkpoint của sprint trước chưa pass.
3. Xong bước → đánh dấu checklist file 69 + ghi kết quả test **thật** vào file 70 (không đánh trước).
4. Vướng mắc / sai lệch thiết kế (68) → ghi Issue log + Deviation ở file 70; không tự đổi thiết kế khi chưa được HUMAN cho phép.
5. Không commit/reset thay đổi sẵn có trong worktree trừ khi HUMAN yêu cầu.

**Dừng và hỏi HUMAN khi:** thiết kế (68) thiếu hoặc mâu thuẫn · test fail 2 lần liên tiếp không rõ nguyên nhân · cần đổi schema/API lớn · cần sửa file ngoài phạm vi sprint.

### A.2. 4 quy tắc bắt buộc

1. **Plan-first:** bám kế hoạch 68; thay đổi thiết kế lớn phải được HUMAN duyệt trước khi làm.
2. **Checkpoint block:** `C*n` chưa pass thì không bắt đầu sprint sau.
3. **Test thật, ghi ngay:** mọi checkbox `[x]` phải có kết quả test tương ứng ghi ở file 70 trong cùng phiên.
4. **1 file 1 lần sửa:** sửa có chủ đích, không viết lại file lớn; mỗi lần thêm route vào `app.js` chỉ edit dòng đó.
