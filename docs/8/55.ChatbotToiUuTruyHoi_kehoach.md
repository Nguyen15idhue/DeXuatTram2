## 1. Bối cảnh

Chatbot hướng dẫn hiện có pipeline 3 lớp:

```
câu hỏi → query rewrite → dataTools (deterministic, regex) → help lexical retrieval
        → knowledge FULLTEXT → build prompt (PHẦN 0/1/2) → LLM (Gemini → OpenRouter)
```

Đã đạt chất lượng tốt ở quy mô hiện tại (~73 bài help, ~95 file tài liệu / ~2853 chunk):

- Eval 104 câu: **103/104 PASS** (`backend/scripts/eval-assistant-100.js`).
- Eval nguồn: **20/20 lấy đúng nguồn** (`backend/scripts/eval-assistant.js`).
- Red-team data-tools: **26/26** (`backend/test-assistant-datatools.js`).
- Kho tri thức + chống lộ secret: **9/9** (`backend/scripts/test-knowledge.js`).
- Router/fallback: **8/8** (`backend/test-assistant-router.js`).

**Kết luận đánh giá**: kiến trúc đã tốt, **chưa cần embedding/vector** (đúng như docs 54 §5). Điểm yếu chính nằm ở **hiệu năng truy hồi & cache**, không phải chất lượng truy hồi.

## 3. Kế hoạch triển khai

### 3.1. P0 — Rẻ, tác động cao (làm trước)

| ID | Việc | File | Cách làm | Verify |
|---|---|---|---|---|
| P0-1 | Cache `articlesVersion()` | `assistantService.js:172-177` | Bọc `ttlCache` key `assistant:articles-version`, TTL 60s | Log giảm số query; câu trả lời không đổi |
| P0-2 | Cache `knowledgeVersion()` + invalidate | `assistantService.js`, `helpService.js`, `scripts/index-knowledge.js` | Thêm `SELECT COUNT(*), MAX(updated_at) FROM assistant_knowledge` (cache 60s) **vào cache key**; gọi `ttlCache.delPrefix('assistant:')` khi article create/update/delete/setStatus | Sửa 1 bài → hỏi lại ra nội dung mới ngay |
| P0-3 | Cache structured-text theo bài | `assistantService.js:203` | `htmlToStructuredText` memo theo `articleId:updated_at` (TTL 10') | Cùng câu hỏi lần 2 nhanh hơn |
| P0-4 | Fix `tokenize` token ngắn | `helpService.js:480-486` | Whitelist `nq, lk, tdt, 3d, api, qr, ip…` (length<3) + match bằng **word-boundary** cho token ngắn | "NQ_LK là gì", "bật 3D" khớp đúng bài |
| P0-5 | Trả thẳng data-tool đơn giản (0 token) | `dataTools.js`, `assistantService.js:326-344` | Gắn `direct:true` cho `get_current_time, count_entities, get_field_types, get_status_labels, get_map_config, get_map_providers, get_geocode_provider, get_help_toc, get_lifecycle_rules` → `ask/askStream` trả text trực tiếp (vẫn `redactPII` + log) | Đếm/giờ/map config trả ngay, không gọi LLM |
| P0-6 | Cache 2 tầng theo câu rewrite | `assistantService.js:277-282` | Thứ tự: check key (có history) → nếu miss thì rewrite → check key **không history** (theo câu rewrite + role + 2 version) → miss mới chạy full | Cache hit tăng ở hội thoại nhiều lượt |

### 3.2. P1 — Chất lượng truy hồi

### 3.4. Không làm (P3 — chỉ khi thực sự cần)

- Embedding/vector "Nấc 3" — chỉ khi **>500 bài** hoặc trượt đồng nghĩa nhiều (docs 54 §5).
- Cross-encoder reranker — overkill ở quy mô hiện tại.

## 7. Phụ lục — Baseline chi phí (tham khảo)

- Mỗi câu hỏi (trung bình) ≈ **~4.600 input + ~350 output token** (system ~840 + tài liệu + history).
- Cache RAM 1h: câu trùng không gọi model (0 token).
- Rate limit: `assistantLimiter` **30/giờ/IP** (`backend/src/middlewares/rateLimits.js:75-81`).
- Đơn giá model rẻ (ví dụ Qwen3.7 Flash qua OpenRouter): input `$0.03`/1M, output `$0.13`/1M → ~`$0,00019`/câu; cache read `$0.006`/1M.
- Mục tiêu tối ưu P0/P1: giảm token input (dedup, cache) và giảm số call (trả thẳng data-tool, cache 2 tầng).
