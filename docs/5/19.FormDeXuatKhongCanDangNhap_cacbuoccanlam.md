## Bước 1 — Database (script SQL thủ công)

- `ALTER TABLE station_proposals MODIFY user_id INT NULL;`
- Thêm `submission_source ENUM('user','guest') DEFAULT 'user'`, `tracking_code VARCHAR(20) NULL`, `submitter_ip VARCHAR(45) NULL`.
- `CREATE INDEX idx_proposals_source`, `CREATE UNIQUE INDEX uq_proposals_tracking`.
- Cân nhắc thêm index `owner_phone` (phục vụ dedupe phone + tọa độ).

### Yêu cầu cần đạt

- [ ] Script chạy được nhiều lần không lỗi (dùng `ADD COLUMN IF NOT EXISTS` kiểu thủ công kiểm tra trước)
- [ ] Không DROP/CREATE lại bảng, không mất dữ liệu cũ

### Checklist test

- [ ] `DESCRIBE station_proposals` có 3 cột mới đúng kiểu
- [ ] Row cũ vẫn đọc/ghi bình thường

### Ghi chú

- Không cần field/script mới cho mã (tái dùng `ma_de_xuat`, sequence, `dm_tinh` của 21/22).

## Bước 2 — Endpoint `POST /api/proposals/guest` + tra cứu

- `POST /api/proposals/guest` (không `requireAuth`): validate cố định + `province` + `mo_hinh_dau_tu`; captcha verify → check trùng <200m (biến thể public) → dedupe phone + tọa độ → `applyDiaGioi` → sinh `tracking_code` + `ma_de_xuat` (chung dãy user) trong transaction → 201.
- `GET /api/proposals/track/:code` (public): rate-limit riêng; sai mã → 404 chung; đúng → 1 proposal, SĐT che giữa.
- `@swagger` JSDoc cả 2 endpoint; `guestLimiter` trong `app.js` (5 req/giờ/IP submit, 30 req/giờ/IP tra cứu).

### Yêu cầu cần đạt

- [ ] Thiếu/tỉnh lạ → 400 + rollback; captcha sai → 400 không INSERT; quá limit → 429
- [ ] Trùng <200m hoặc cùng SĐT trong 200m → 400 kèm thông báo
- [ ] `tracking_code` unique, không đoán được; `ma_de_xuat` đếm chung dãy user login

### Checklist test

- [ ] Submit đủ → 201 + đủ 2 mã + `PENDING` + `user_id NULL`
- [ ] Submit thiếu tỉnh/tỉnh lạ/captcha sai/quá limit → mã lỗi đúng + DB không thêm row
- [ ] Submit trùng vị trí / cùng SĐT gần nhau → 400
- [ ] Tra cứu đúng → chi tiết 1 đề xuất; sai → 404
- [ ] Swagger hiện 2 endpoint mới

### Ghi chú

- Không sửa `POST /api/proposals` cũ. `TURNSTILE_SECRET_KEY` trong `.env`.

## Bước 3 — LEFT JOIN + hiển thị "Khách"

- Đổi `JOIN users` → `LEFT JOIN` ở `proposalService` (list/byId/sau create) và `adminProposalService` (list + count).
- Admin table/map/export hiển thị "Khách" khi `user_name` null. Duplicates/check-nearby không JOIN nên tự bao gồm guest.

### Yêu cầu cần đạt

- [ ] Đề xuất guest hiện ở list admin, map, export, kết quả trùng
- [ ] Không vỡ search có JOIN (`owner_name/address/user_name`)

### Checklist test

- [ ] Tạo guest → thấy ở admin list + map + export + duplicates
- [ ] Search theo tên người tạo vẫn chạy

### Ghi chú

- AGENTS.md rule #4 cập nhật sau bước này (`user_id` được NULL với guest).

## Bước 4 — Trang `/de-xuat` + localStorage

- Route public `PublicLayout`: hero/CTAs tối thiểu + form (`DynamicForm` form 9, **giữ field file** cho guest) + **lấy vị trí bằng "Vị trí của tôi" (geolocation) hoặc dán link Google Maps** (không nhúng map click) + captcha widget + honeypot.
- Upload qua endpoint public riêng `POST /api/files/guest-upload` (ảnh + PDF/DOC, ≤ 5MB/file, tối đa 5 file/đề xuất); submit gửi kèm file id để backend verify + gắn.
- Check-nearby chạy ngay khi có lat/long (cảnh báo sớm) + chặn cuối lúc submit.
- Màn hình kết quả: cả 2 mã + nút copy + nhắc tự lưu.
- Khối "Đề xuất của bạn" (`localStorage`, tối đa 20-50) + ô nhập mã tay + nút xóa.

### Yêu cầu cần đạt

- [ ] Không login vẫn mở form, submit, tra cứu được
- [ ] Upload đúng loại/dung lượng thì gắn được vào đề xuất; sai loại/quá 5MB/quá 5 file → lỗi rõ ràng
- [ ] Reload trang vẫn thấy list mã; xóa cache thì mất nhưng nhập tay vẫn tra được

### Checklist test

- [ ] Ẩn danh hoàn thành 1 đề xuất end-to-end (chọn map → nhập → upload file → submit → copy mã → tra cứu)
- [ ] Thử upload sai loại/quá dung lượng/quá số lượng → lỗi đúng; file mồ côi quá 24h bị dọn
- [ ] Mobile hiển thị ổn (khách đa số dùng điện thoại)

### Ghi chú

- Nội dung landing đầy đủ (hero/lợi ích/FAQ...) thuộc mục 6 file kế hoạch — làm sau khi form chạy.
