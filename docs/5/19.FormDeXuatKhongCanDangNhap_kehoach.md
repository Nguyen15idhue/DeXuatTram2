# Kế hoạch: Form đề xuất không cần đăng nhập

> **Cập nhật 04/09/2026 theo `21.Checkloctrung_kehoach.md` (21 là bản mới nhất)**: endpoint guest dùng chung logic sinh `ma_de_xuat` + check trùng <200m của 21; giữ `tracking_code` riêng để khách tra cứu. Thứ tự làm: **21 trước → 19 sau** (21 tạo fields/DataList/SEQ, 19 tái dùng).

## 1. Mục tiêu
- Khách vãng lai (chưa đăng nhập) vẫn điền và gửi form đề xuất trạm được.
- Giữ nguyên luồng user đã đăng nhập (`POST /api/proposals` + `requireAuth`).
- Chống spam là yêu cầu bắt buộc (form public).

## 2. Hiện trạng (ràng buộc)
- `POST /api/proposals` bắt `requireAuth` (`backend/src/routes/proposals.js:121`).
- `station_proposals.user_id INT NOT NULL` + FK về `users(id)` (`database/01-create-tables.sql:49-63`).
- Các query list dùng `JOIN users` (inner) trong `proposalService.js`, `adminProposalService.js` → row có `user_id = NULL` sẽ biến mất khỏi kết quả.
- `POST /api/dynamic/:entity/validate` yêu cầu JWT (`backend/src/routes/dynamicEngine.js:98`).
- `POST /api/files/upload` yêu cầu JWT.
- Frontend form đề xuất nằm trong `UserLayout` (tự redirect về `/login` khi chưa login).
- Rule AGENTS.md #4 "Proposal phải lưu user_id" sẽ phải sửa thành "user_id được NULL với guest".

## 3. Thiết kế

### 3.1 Database (script SQL thủ công, không DROP TABLE)
```sql
ALTER TABLE station_proposals MODIFY user_id INT NULL;
ALTER TABLE station_proposals ADD COLUMN submission_source ENUM('user','guest') NOT NULL DEFAULT 'user';
ALTER TABLE station_proposals ADD COLUMN tracking_code VARCHAR(20) NULL;
ALTER TABLE station_proposals ADD COLUMN submitter_ip VARCHAR(45) NULL;
CREATE INDEX idx_proposals_source ON station_proposals(submission_source);
CREATE UNIQUE INDEX uq_proposals_tracking ON station_proposals(tracking_code);
```
- `tracking_code`: mã tra cứu cho khách (VD `DX-XXXXXX`), sinh ở backend khi tạo. Giữ song song với `ma_de_xuat` của 21 (2 mã, 2 mục đích khác nhau — xem 3.2).
- Không cho khách sửa/xóa → không cần cơ chế chủ sở hữu cho guest.
- Thứ tự script SQL: chạy script của **21 trước** (`dm_tinh`/`dm_xa`, 3 field_definitions, bảng `proposal_sequences`), rồi mới chạy script của file này.

### 3.2 Backend
1. **Endpoint mới** `POST /api/proposals/guest` (không `requireAuth`):
   - Dùng chung `validateCreateProposal` như endpoint cũ **+ validate 3 fields của 21** (`mo_hinh_dau_tu`, `ma_tinh` bắt buộc).
   - `user_id = NULL`, `status = 'PENDING'`, sinh `tracking_code`, lưu `submitter_ip`.
   - Sinh `ma_de_xuat` **bằng đúng hàm `SEQ(prefix)` của 21** (transaction + `FOR UPDATE`, prefix `{MaMoHinh}_{MaTinh}`, đếm chung với proposal của user login — không tách dãy số).
   - 2 mã cùng tồn tại: `tracking_code` để **khách tra cứu** (public, không đoán được), `ma_de_xuat` để **quản trị/đối chiếu** (hiển thị admin/table).
   - Verify captcha server-side (Turnstile/reCAPTCHA) trước khi INSERT.
   - Rate limit riêng, chặt (VD 5 req/giờ/IP) — hiện route public chưa có limiter nào.
   - Gọi **check trùng <200m của 21 trước khi INSERT** (dùng biến thể public của `POST /api/proposals/check-nearby`, không yêu cầu JWT, có rate-limit + captcha như endpoint guest). Trùng → 400 + thông báo như user login.
   - Thêm `@swagger` JSDoc trong route file.
2. **Chuyển `JOIN users` → `LEFT JOIN`** trong:
   - `backend/src/services/proposalService.js` (`getAllProposals`, `getProposalById`, select sau create)
   - `backend/src/services/adminProposalService.js` (list + count đã sửa JOIN cho search)
   - API duplicates của 21 (`GET /api/admin/proposals/duplicates`, `GET /api/my-proposals/duplicates`) cũng phải `LEFT JOIN` — row guest không được rớt khỏi kết quả trùng.
   - Hiển thị `user_name = NULL` → "Khách" (áp dụng cả table trùng + View map tooltip của 21).
3. **Validate public**: mở `POST /api/dynamic/station_proposals/validate` cho phép không JWT (chỉ entity này), hoặc bỏ validate client, giữ validate backend.
4. **File**: bản guest **ẩn field loại `file`** (khuyến nghị). Nếu cần upload thì làm endpoint upload public riêng sau (giới hạn loại file, captcha).

### 3.3 Frontend
1. Trang public mới (VD `/de-xuat`), dùng `PublicLayout`:
   - Tái dùng `DynamicForm` + bản đồ click lấy lat/lng (đúng rule map hiện tại).
   - Form guest **phải gồm đủ 3 fields của 21**: `mo_hinh_dau_tu` (label tiếng Việt), `ma_tinh` (select từ `dm_tinh`), `ma_de_xuat` hiển thị "Tính sau khi lưu".
   - Gọi endpoint guest, không gửi token; thêm captcha widget + honeypot field.
   - Trước submit gọi check-nearby public (<200m → chặn + toast như 21 case 1).
   - Màn hình kết quả hiện **cả 2 mã**: `tracking_code` (để tra cứu) + `ma_de_xuat` (để đối chiếu).
2. Admin (`AdminProposalsPage`): cột người tạo hiển thị "Khách" khi `user_name` null; search hiện tại (`owner_name/address/user_name`) vẫn chạy với `LEFT JOIN`.

### 3.4 Chống spam
- Rate limit theo IP (bắt buộc).
- Captcha bắt buộc (server verify).
- Validate phone VN, giới hạn độ dài `description`, log IP, dedupe theo phone + tọa độ (dedupe tọa độ = **case 1 của 21**: <200m chặn, dùng chung `haversineM`).

### 3.5 Tra cứu bằng tracking code (public, không đăng nhập)

1. **Endpoint mới** `GET /api/proposals/track/:code` (không `requireAuth`):
   - Rate limit theo IP (VD 30 req/giờ/IP) — mã là bearer token, chống dò quét.
   - Sai mã → 404 chung chung (không tiết lộ mã nào tồn tại).
   - Trả đúng 1 proposal của mã đó, SĐT **che giữa** (VD `09***1234`).
   - Thêm `@swagger` JSDoc trong route file.
2. **Nội dung khách thấy**: `ma_de_xuat`, `tracking_code`, trạng thái (diễn giải tiếng Việt) + ngày gửi; mô hình (tiếng Việt), tỉnh/xã, địa chỉ, diện tích, loại đất, mô tả, tọa độ điểm của chính họ.
3. **Không thấy**: đề xuất của người khác, list/map tổng, thông tin user khác, ghi chú nội bộ admin, nút sửa/xóa.

### 3.6 Danh sách mã trên máy khách (localStorage)

- Submit guest thành công → push `{tracking_code, ma_de_xuat, created_at}` vào `localStorage` (key VD `guest_proposals`), tối đa 20-50 mã (cũ nhất tự rớt). Dùng `localStorage` (giữ sau khi đóng trình duyệt), **không** dùng `sessionStorage`.
- Chỉ lưu mã — chi tiết lấy từ API 3.5 mỗi lần mở (không lo dữ liệu cũ, không lộ thông tin cá nhân).
- Trang `/de-xuat` có khối "Đề xuất của bạn": list mã đã lưu → bấm xem chi tiết (3.5) → nút xóa mã khỏi list. Kèm ô nhập mã thủ công (tra mã của máy khác).
- Danh sách **theo máy/trình duyệt**: xóa cache/đổi máy là mất → màn hình kết quả sau submit vẫn hiện mã + nút copy, nhắc khách tự lưu.
