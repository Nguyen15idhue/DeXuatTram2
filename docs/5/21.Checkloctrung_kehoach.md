## Yêu cầu 1: Formula post — Trường `ma_de_xuat` (`NQ_HNO_0001`)

### Mô tả

- Định dạng: `{MaMoHinh}_{MaTinh}_{Sequence4}`. VD: `NQ_HNO_0001`.
- `MaMoHinh`: value gốc của field `mo_hinh_dau_tu` (`NQ` / `TDT` / `LK`). Table/form hiển thị label tiếng Việt đầy đủ (Nhượng quyền / Tự đầu tư / Liên kết), DB chỉ lưu mã ngắn, formula dùng mã ngắn.
- `MaTinh`: value gốc của field `ma_tinh` (lấy từ Data List `dm_tinh`, VD `HNO`). Table/form hiển thị label `ten_tinh` (VD `Thành phố Hà Nội`), DB chỉ lưu mã, formula dùng mã. Không tự suy mã từ tên tỉnh.
- `Sequence4`: đếm riêng từng prefix, format 4 chữ số (`0001`, `0002`...), chống trùng khi 2 user submit đồng thời.
- Sinh **1 lần lúc create** (post-compute sau INSERT). Update giữ nguyên. Import tự sinh.

### Hiện trạng chặn (đã khảo sát)

- `mo_hinh_dau_tu`, `ma_tinh`, `ma_de_xuat` **chưa tồn tại** trong DB/backend/frontend.
- `computePostFormulas` (`backend/src/services/dynamicEngineService.js:166-197`) chỉ nhận 6 metadata, bỏ qua `recordData` → post-formula không đọc được field cùng record.
- `evaluatePostFormula` (`backend/src/services/formulaService.js:86-100`) không truy vấn DB → không đếm sequence.
- `myProposalService.js:60-72` update không recompute post (đúng ý yêu cầu 6 — giữ nguyên mã).

### Files cần sửa/tạo

- DB (SQL scripts thủ công, **không DROP TABLE, không migration tool**):
  - Script seed Data List `dm_tinh` (34 rows: `ma_tinh, ten_tinh, vung_mien`) + `dm_xa` (3321 rows, `parent_row_id` → tỉnh).
  - Script seed `field_definitions`: `mo_hinh_dau_tu` (select manual), `ma_tinh` (select từ Data List), `ma_de_xuat` (formula post).
  - Script tạo bảng `proposal_sequences(prefix VARCHAR(20) PK, last_number INT, updated_at)`.
  - `ma_de_xuat` lưu trong `custom_data` JSON + unique logic (không unique constraint trực tiếp được trên JSON → enforce ở service + index phụ nếu cần).
- Backend:
  - `backend/src/services/dynamicEngineService.js` — truyền `recordData` vào scope post + hàm `SEQ(prefix)`.
  - `backend/src/services/formulaService.js` — thêm `MODEL_CODE()`, `SEQ()` (query `proposal_sequences` với `FOR UPDATE`).
  - `backend/src/services/proposalService.js` — bọc create trong transaction (INSERT → compute post có lock → UPDATE `custom_data`).
  - `backend/src/services/excelService.js` — template thêm cột mã để trống + ghi chú; import gọi sinh mã.
  - `backend/src/routes/formulas.js` — Swagger cho preview post mới.
- Frontend:
  - `frontend/src/components/dynamic/FormulaEditor.jsx` — preset expression mã đề xuất.
  - `frontend/src/components/dynamic/DynamicForm.jsx` — field post hiển thị "Tính sau khi lưu" (giữ nguyên).
  - Label/value mapping: `FieldRenderer.jsx:78` (table) và `DynamicField.jsx:175` (form) đã render `opt.label` → hiển thị tiếng Việt, không cần sửa cho `mo_hinh_dau_tu`. Riêng `ma_tinh` cần sửa nhỏ `FieldRenderer.jsx:49-56` + `DynamicForm.jsx:205-226` để `value` lấy từ cột `ma_tinh`, `label` lấy từ `ten_tinh` qua `_raw` (code hiện tại mặc định value=label cùng 1 cột: `useDataList.js:24-25`, `useDataListMap.js:15`).

### Chi tiết bước thực hiện

#### Bước 1.1: Import Data List địa giới

- Python đọc `test_files/Danh-muc-Phuong-xa_moi.xlsx` (bỏ cột D, sort tỉnh+xã vì STT cuối file lộn).
- `INSERT data_lists (dm_tinh: columns_config=[ma_tinh, ten_tinh, vung_mien])`, `INSERT data_list_rows` 34 rows.
- `INSERT data_lists (dm_xa: columns_config=[ten_xa])`, `INSERT data_list_rows` 3321 rows với `parent_row_id` trỏ tỉnh tương ứng.

#### Bước 1.2: Tạo 3 field_definitions

- `mo_hinh_dau_tu`: type `select`, `source_type=json`, manual options (value gốc là mã ngắn, label tiếng Việt đầy đủ hiển thị ở table/form):
  `[{value: NQ, label: Nhượng quyền}, {value: TDT, label: Tự đầu tư}, {value: LK, label: Liên kết}]`, required.
- `ma_tinh`: type `select`, `source_type=json`, `data_list_id=dm_tinh`, `data_list_column=ma_tinh`, required. Giá trị lưu là `ma_tinh` (mã có sẵn trong Data List, không tự suy từ tên). Label hiển thị là `ten_tinh` (map qua `_raw`).
- `ma_de_xuat`: type `formula`, `compute_mode=post`, `formula_config={expression, outputType: text}`, readonly, required-sau-sinh.

#### Bước 1.3: Mở rộng engine post

- `computePostFormulas(entity, recordId, recordData, ...)`: merge `recordData` vào scope (kèm `MODEL_CODE(mo_hinh_dau_tu)` → NQ/TDT/LK).
- `SEQ(prefix)`: `SELECT last_number ... FOR UPDATE` → +1 → `UPDATE` → `LPAD(n,4,'0')`. Prefix = `{MaMoHinh}_{MaTinh}`.
- Transaction trong `createProposal`: `START TRANSACTION → INSERT → SEQ → UPDATE custom_data → COMMIT`.

#### Bước 1.4: Import Excel

- Template: thêm cột `ma_de_xuat` với comment "Bỏ trống — hệ thống tự sinh".
- Preview/confirm import: bỏ qua giá trị cột mã trong file, sinh mã cho từng dòng hợp lệ.

## Ghi chú

- **DB quản lý thủ công qua SQL scripts** (không migration tool, không DROP/CREATE lại bảng). Mỗi thay đổi 1 file `.sql` mới trong `database/`.
- **Station và Station Proposal độc lập**: không merge entity, không thêm status `PROPOSAL` vào Station.
- **lat/long từ click map**, không nhập thủ công (giữ nguyên flow `MapPage` + modal create).
- **Rủi ro chính**: race condition sinh mã → giải quyết bằng `FOR UPDATE` + transaction; O(n²) duplicates → chặn max 5000m + bounding box.
- **Không push GitHub** — user check thủ công trước (theo quy ước docs/5).
