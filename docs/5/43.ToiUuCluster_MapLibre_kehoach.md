## 1. Tổng quan vấn đề

Cùng một bộ dữ liệu marker (trạm + đề xuất), Leaflet pan/zoom mượt nhưng MapLibre (renderer vector/MapLibre) hay giật, khựng.

### 1.1. Bản chất khác nhau giữa 2 renderer

| | Leaflet (`leafletRuntime.js`) | MapLibre (`maplibreRuntime.js`) |
|---|---|---|
| Engine cluster | Plugin `leaflet.markercluster` | GeoJSON source `cluster: true` (supercluster trong Worker) |
| Đơn vị render | `L.marker` = DOM/divIcon | Circle/symbol layer = GPU |
| Tính cluster | Main thread, chia lô (`requestAnimFrame`) | Worker |
| Vòng đời | Chỉ tính lại khi `zoomend`/`moveend` | Re-cluster + re-place symbol khi dữ liệu/style đổi |
| Tile nền | Raster PNG (render sẵn) | Vector 111–117 layer, style/GPU mỗi frame |

**Kết luận**: không phải thuật toán cluster của MapLibre chậm (supercluster chạy trong Worker), mà do **cách code quản lý vòng đời source/layer** + **khối lượng GPU phải vẽ mỗi frame** lớn hơn Leaflet rất nhiều.

### 1.2. Nguyên nhân gốc (đối chiếu code)

| # | Vấn đề | Vị trí |
|---|--------|--------|

## 3. Thiết kế chi tiết

### 3.1. Fix 1 — Bỏ `clearOverlays()` khỏi `applyAll`

- Thay `clearOverlays()` bằng `removeDomOverlays()`: chỉ xóa **DOM marker** (station/province/point) + đóng popup; **không** xóa source/layer.
- Prune `sourceIds`: id nào không còn source (do `setStyle` đã xóa) thì bỏ khỏi Set.
- `removeManagedSource(id)` xóa id khỏi Set kể cả khi source đã mất.
- `applyMarkers`:
  - nhánh `!cluster`: gọi `removeManagedSource('app-markers')` trước khi tạo DOM marker (tránh tồn 2 lớp khi toggle cluster).
  - nhánh cluster: xóa DOM marker trước; nếu source đã tồn tại → chỉ `setData`.
- `applyWardLabels` vẫn được phép `removeManagedSource(SRC)` (dữ liệu nhãn thay đổi theo layer).

### 3.2. Fix 2 — Guard `applyAll` chạy 1 lần

- `onStyleReady` chỉ chạy `applyAll()` khi cần: dùng cờ `styleApplied`/so sánh.
- Giữ `map.on('load', ...)` cho lần đầu; `style.load` chỉ xử lý khi `setStyle` (đã có `map.once('style.load', applyAll)` trong `setStyle`).
- Tránh add `NavigationControl` lặp (đã có `navAdded`).

### 3.3. Fix 3 — `bringOverlaysToTop` theo cờ dirty

- Thêm `let overlayOrderDirty = false;`
- Set `true` mỗi khi `addLayer` một layer thuộc `overlayTopOrder`.
- `bringOverlaysToTop()` return sớm nếu `!overlayOrderDirty`; sau khi chạy set `false`.

### 3.4. Fix 4 — Cluster gộp lâu hơn

- `clusterMaxZoom: 18`, `clusterRadius: 70`.

### 3.5. Fix 5 — Ward labels theo viewport

- `minzoom: 12`.
- `wardState` giữ toàn bộ điểm; thêm `refreshWardData()`: lọc điểm trong `map.getBounds().pad(0.15)`, cap **400** (hằng `WARD_MAX_LABELS`), `setData` cho source `app-ward-labels`.
- Gọi `refreshWardData()` khi `zoomend`/`moveend` (giống Leaflet) — chỉ khi `show` và `zoom ≥ 12`.

### 3.6. Fix 6 — Marker labels

- Thêm `minzoom` (14) cho layer `app-marker-labels`.
- Thêm runtime method `setMarkerLabels(show)`: `addLayer`/`removeLayer` (bọc try/catch vì style thiếu glyphs).
- `MapCanvas` tách effect nhãn riêng, gọi `setMarkerLabels`.

### 3.7. Fix 7 — `setPixelRatio` động

- Trong `setMarkers`: nếu `items.length > 2000` → `setPixelRatio(1)`; ngược lại `min(dpr, 1.5)`.

### 3.8. Fix 8 — MapCanvas guard

- Tách effect `setMarkers` (data) khỏi effect nhãn.
- Guard bằng ref signature `{stations, proposals, cluster}` — trùng reference thì bỏ qua.

## 7. Ghi chú

- `setPixelRatio` hiện tính lại trong `applyMarkers` theo số marker (> 2000 → 1).
- Terrain/3D vẫn theo `map_configs.enable_3d` (không đổi mặc định để tránh phá cấu hình admin). Nếu muốn giảm tải hơn, cân nhắc tắt `enable_3d` trong cấu hình bản đồ.
- Không đổi API runtime cũ; chỉ thêm `setMarkerLabels` (MapLibre) — MapCanvas guard bằng `typeof`.
