# Kế hoạch Stress Test & Performance Test

## Mục tiêu
- Xác định giới hạn chịu tải của hệ thống
- Tìm bottleneck (CPU, RAM, DB connections, response time)
- Đảm bảo hệ thống ổn định dưới tải thực tế

## Công cụ
- **k6** (JavaScript-based load testing) — chính
- **MySQL slow query log** — kiểm tra query chậm
- **Docker stats** — monitor CPU/RAM containers
- **Browser DevTools** — kiểm tra frontend performance

## Lưu ý môi trường (bắt buộc đọc trước khi test)
- Backend trong Docker đang chạy `npm run dev` = `node --watch` → số liệu chỉ mang tính tham khảo, **không phải số production**. Khi cần số production: `docker exec station-backend node src/app.js` (hoặc build image prod riêng).
- Rate limit bản dev: auth **30 req/phút**, admin **120 req/phút**, excel **30 req/phút** (bản prod: 10 / 60 / 10). Mọi scenario vượt ngưỡng này sẽ nhận **429** — đó là hành vi đúng, không phải lỗi hệ thống. Test vượt ngưỡng để ở Phase 6, không trộn vào Phase 2.
- DB pool: `connectionLimit: 10`, `queueLimit: 0` (chờ không giới hạn) — tải cao sẽ xếp hàng ở pool, phải monitor `Threads_running`.
- k6 chạy trên **host** (không chạy trong cùng container backend) để tránh tranh CPU.
- Test POST sẽ **làm bẩn DB** (tạo proposals/users/files thật) → snapshot/backup DB trước khi chạy, có bước dọn dữ liệu test sau khi xong.
- Bundle JS hiện tại ~640KB gzip (index 517KB + leaflet 91KB + css 32KB) → target Phase 4 phải đo từ baseline này, không đặt target thấp hơn thực tế.

**Phát hiện quan trọng (không phải bug hệ thống — là test sai, đã sửa):**
1. `GET /api/auth/me` nằm trong router `/api/auth` → dính `authLimiter` (dev 30/phút). Bản test đầu bắn ~60 req/s → 100% **429**. Đã sửa: login 1 lần ở `setup()` + `/me` chỉ sampling thưa, tải chính dồn vào `my-proposals` (không limit).
2. Lần chạy 2b đầu fail 100% cả 2 endpoint vì lần chạy bị abort trước đó đã trip limiter → `setup()` login dính 429 theo → token undefined → loạt 401. Bài học: **chờ hết window 60s trước mỗi lần chạy có login**.
3. Bản test admin 5 VUs (~25 req/s) vượt `adminLimiter` dev (120/phút = 2/s) → 92% **429**. Verify: chờ hết window → API 200 bình thường. Đã sửa về 1 VU (~1 req/s) → pass. Số 429 này là bằng chứng limiter hoạt động (dùng cho Phase 6).

## Phase 3: Database Performance

### Kết quả Phase 3 (chạy ngày 2026-09-03) — ✅ PASS (3.3 soak tạm bỏ qua theo yêu cầu)

**3.1 Query analysis:**
- Full scan là bình thường ở scale hiện tại (bảng lớn nhất 3,321 rows): stations/proposals list ~11.6K lượt (từ Phase 2), mỗi lượt quét ~100-120 rows, avg <0.5ms.
- Query nóng nhất: `field_definitions WHERE entity=? AND status=?` — 46K lượt (mỗi API request gọi 1 lần). Index hiện có `idx_entity` + `idx_status` riêng lẻ → **khuyến nghị thêm composite index `(entity, status)`**.
- `LIKE '%keyword%'` không dùng index được (wildcard đầu) — chấp nhận ở scale này; khi >100K records cân nhắc FULLTEXT.
- InnoDB buffer hit rate **99.99%** (reads=1135 / requests=7,966,737).
- Slow log (>1s) ghi nhận **2 queries**: `SELECT * FROM field_definitions WHERE entity=...` mất ~2.5s (2 lần, giữa lúc Phase 2 bắn 50 VUs) — nghi lock/CPU contention lúc tải cao, không phải lỗi query (bảng chỉ 32 rows). Cần theo dõi lại khi chạy stress 200 VUs.

## Script k6 cơ bản

```javascript
// test/stress-test.js
import http from 'k6/http';
import { check, sleep, group } from 'k6';

export const options = {
  stages: [
    { duration: '1m', target: 10 },   // Warm-up
    { duration: '3m', target: 30 },   // Normal
    { duration: '3m', target: 100 },  // Peak
    { duration: '3m', target: 200 },  // Stress
    { duration: '1m', target: 500 },  // Spike
    { duration: '2m', target: 30 },   // Recovery
  ],
  thresholds: {
    http_req_duration: ['p(95)<1000', 'p(99)<3000'],
    http_req_failed: ['rate<0.1'],
  },
};

const BASE_URL = 'http://localhost:3000';

// Login 1 lần, tái dùng token — không login mỗi iteration
export function setup() {
  const res = http.post(`${BASE_URL}/api/auth/login`, JSON.stringify({
    email: 'admin@station.com', password: '123456',
  }), { headers: { 'Content-Type': 'application/json' } });
  return { token: res.json('data.token') };
}

export default function (data) {
  const auth = { headers: { Authorization: `Bearer ${data.token}` } };

  group('public', () => {
    let res = http.get(`${BASE_URL}/api/stations`);
    check(res, { 'stations 200': (r) => r.status === 200 });
    res = http.get(`${BASE_URL}/api/proposals`);
    check(res, { 'proposals 200': (r) => r.status === 200 });
    res = http.get(`${BASE_URL}/api/field-definitions/entity/stations`);
    check(res, { 'fields 200': (r) => r.status === 200 });
  });

  group('auth', () => {
    const res = http.get(`${BASE_URL}/api/my-proposals`, auth);
    check(res, { 'my-proposals 200': (r) => r.status === 200 });
  });

  sleep(1);
}
```
