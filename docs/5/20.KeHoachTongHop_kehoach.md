## P1. Map fallback chain (nhỏ — 1 file frontend)

### Vấn đề
- Sau đợt fix CARTO, fallback **trùng URL chính** (cùng OSM) → "tự chuyển về mặc định" thực chất không chuyển đi đâu; banner hiện trong khi tiles vẫn lỗi → cảm giác lỗi loop.
- Test dồn 30 request OSM bị timeout hàng loạt → dựa vào 1 nguồn miễn phí duy nhất là mong manh (tile usage policy siết tải).

### Việc cần làm (`frontend/src/components/MapView.jsx`)
1. `FALLBACK_TILES` thành **chuỗi khác nguồn**: OSM → Esri World Street Map → OpenTopoMap.
2. `handleTileError` thử lần lượt chuỗi fallback thay vì gán cứng URL đầu; mỗi URL chỉ cảnh báo 1 lần (guard theo URL, tránh spam banner).
3. Banner区分 2 trạng thái: "đang thử nguồn khác..." (tạm) vs "đã dùng bản đồ mặc định" (chốt).
4. Cooldown trước khi quay lại URL chính (VD chỉ thử lại khi user đổi provider/style hoặc reload trang).

> Tương thích 21: 21 thêm prop `highlightIds` (chỉ hiện điểm trùng) vào cùng `MapView.jsx` — gộp chung 1 lần sửa, không tách 2 đợt (tránh conflict). Fallback tiles và highlightIds độc lập, không đè nhau.

## P2. Trường table cơ bản (chưa formula)

### Mục tiêu
- 1 field bảng nhiều dòng trong form (VD "Danh sách sản phẩm": sản phẩm / số lượng / tổng giá).
- Header = cột **tham chiếu** field definition (lưu `field_id` + override riêng cho table: label, width, required) — không dùng trực tiếp field vì 1 field có thể nằm nhiều table.
- Thêm/xóa dòng + `min_rows`/`max_rows`; hàng footer tách riêng (ô đầu là text "Tổng cộng", các ô sau là formula — footer không đếm vào min/max, không xóa được).
- Lưu mảng JSON trong `custom_data`, VD `"line_items": [{ "san_pham": "Trụ A", "so_luong": 2, "tong_gia": 500000 }]`.
- Địa chỉ ô theo chuẩn JSONPath: `tableKey[rowIndex].columnKey` (VD `line_items[0].so_luong`).
- Hiển thị như `repeater_mockup.html` (ô gọn "📋 N dòng" + popup chi tiết).

### Hiện trạng
- 13 field types đều là field đơn; `DynamicForm`/`DynamicField` render field phẳng; `FieldRenderer`/`DynamicTable` hiện 1 giá trị/ô.
- `form_fields.config` đã có tiền lệ pivot (override theo form) — tái dùng pattern này cho cột table.

### Backend — files cần sửa
- `backend/src/controllers/fieldDefinitionController.js`: thêm `table` vào `allowedTypes` (create + update).
- `backend/src/services/fieldDefinitionService.js`: cho phép lưu config cột (`columns: [{field_id, label_override, width, required, footer_formula}]`, `min_rows`, `max_rows`).
- `backend/src/services/dynamicUtils.js` (`splitData`/`mergeData`): cho mảng table đi qua như dynamic value, không stringify 2 lần.
- `backend/src/middlewares/validators.js`: rule validate table — số dòng min/max, validate từng ô theo type của field được tham chiếu, footer không tính là data row.

### Frontend — files cần sửa
- `frontend/src/hooks/useDataListMap.js` (đã có): tái dùng để load options cho cột select trong dòng.
- `frontend/src/components/dynamic/DynamicForm.jsx`: state `formData[tableKey]` là mảng; logic thêm/xóa dòng; lỗi validate theo đường dẫn `tableKey[row].col`.
- `frontend/src/components/dynamic/DynamicField.jsx`: thêm case `table` render bảng + footer + nút thêm/xóa; tái dùng renderer ô hiện tại (select/number/text...).
- `frontend/src/components/admin/FormBuilder.jsx`: panel cấu hình cột (chọn field có sẵn, override label/width/required, set footer formula, min/max rows).
- `frontend/src/components/dynamic/FieldRenderer.jsx` + `DynamicTable.jsx`: ô gọn + popup chi tiết (tái dùng `dataListOptions` đã nối ở đợt fix tower_type).

## P3. Formula cho table (làm SAU 21 — chung engine)

> 21 mở rộng `formulaService.js` + `dynamicEngineService.js` trước (post-scope `recordData` + hàm `SEQ()`). P3 thêm tiếp row-scope + `SUM/AVG/MIN/MAX/COUNT` trên cùng 2 file — làm nối tiếp, không song song. `SEQ()` của 21 và aggregation của P3 tồn tại song song, không đè nhau.

### Mục tiêu (2 loại)
- **Trong dòng:** `tong_gia = so_luong * don_gia` — tên cột tự hiểu là ô cùng dòng, ô kết quả khóa sửa.
- **Footer/tổng hợp:** `SUM(table.col)` (+ `AVG/MIN/MAX/COUNT`), VD `SUM(line_items.tong_gia)`; footer mỗi cột có formula riêng trong config.

### Việc cần làm
- Frontend (`DynamicForm.jsx` `computeFormula`, mathjs): thêm scope dòng (evaluate expression với context = object dòng) + hàm aggregation trên mảng (`SUM/AVG/MIN/MAX/COUNT` nhận mảng trích từ cột).
- Backend (`backend/src/services/formulaService.js` + `dynamicEngineService.js`): cùng 2 loại scope để tính lại khi lưu (chống giả mạo số) + validate expression mới trong `POST /api/formulas/validate` và preview trong `POST /api/formulas/preview`.
- `frontend/src/components/admin/FormulaEditor.jsx`: gợi ý tên cột dạng `table.col`, hint hàm aggregation, autocomplete theo scope. Kế thừa preset + metadata post (`id`, `entity`, `SEQ()`) của 21 — editor hiện cả 2 nhóm gợi ý (post + table).
- Ô footer render giá trị đã tính (readonly), cập nhật live khi sửa dòng.

- [ ] Lưu → backend tính lại khớp frontend (thử giả số ở request).

## P4. Section hiển thị + tách form create/view

### Mục tiêu
- Form gom field vào section viền mờ + tiêu đề (VD "Thông tin liên hệ": họ tên/email/SĐT; "Thông tin trạm": địa chỉ/tọa độ/ảnh). **Chỉ đổi hiển thị, dữ liệu giữ nguyên.**
- Popup view/edit (`RecordDetailPopup`) bỏ chia "Thông tin chính / Thông tin khác", render theo sections của form.
- Trang admin/forms chia 2 cấu hình riêng: form create + form view/edit.

### Hiện trạng (đã kiểm tra code)
- `layout_config` hiện chỉ có `{rows: [{id, columns}]}` — chưa có khái niệm section.
- Bảng `forms` (`database/06-create-forms.sql`) **chưa có cột purpose**.
- `RecordDetailPopup.jsx:214-215,279-280` đang chia mainFields (cột trong view) / otherFields.

### Việc cần làm
1. **DB (script SQL thủ công):** `ALTER TABLE forms ADD COLUMN purpose ENUM('create','view','all') NOT NULL DEFAULT 'all'`; `layout_config` thêm `sections: [{id, title, collapsible, rowIds}]` (row không gán section render như cũ — tương thích ngược). Chạy sau script của 21.
2. **Backend:** `formService`/`formFieldService` lọc theo purpose; API trả sections kèm fields; `@swagger` cho param mới.
3. **FormBuilder:** tạo/kéo section, kéo thả row vào section, cấu hình tiêu đề + thu gọn. 3 fields của 21 (`mo_hinh_dau_tu`, `ma_tinh`, `ma_de_xuat`) phải được xếp vào section (VD "Thông tin đề xuất"); `ma_de_xuat` readonly ở cả 2 bản create/view.
4. **DynamicForm:** render fieldset viền mờ + legend theo sections.
5. **RecordDetailPopup:** lấy sections của form view → render thay 2 nhóm cũ; fallback 2 nhóm cũ nếu form chưa có sections. Giữ cách hiển thị label/value của 21 (`mo_hinh` hiện tiếng Việt, `ma_tinh` hiện tên tỉnh).
6. **admin/forms page:** quản lý 2 bản create/view trên 1 màn hình (tab hoặc 2 panel).
