## 1. Bối cảnh & mục tiêu

Hệ thống đề xuất trạm cần gửi **người phụ trách / người giao phụ trách** sang 1Office. Mỗi bên có danh sách người dùng riêng với **không gian ID riêng** (hệ thống này dùng `users.id`; 1Office dùng ID của nó). Hiện chưa có loại trường "người" nên chưa map được.

**Mục tiêu:**
1. Thêm loại trường **`user`** vào hệ thống dynamic (hiển thị tên, lưu id nội bộ, ấn xem chi tiết user).
2. Lưu **ID hệ ngoài** tập trung bằng bảng `user_external_map` để map sang nhiều nền tảng.
3. Map 2 trường 1Office: `user_ids` (Phụ trách) và `manager_user_ids` (Người giao phụ trách).
4. Đảm bảo dùng **ID** cả hai chiều (không phụ thuộc tên).

## 4. Thiết kế

### 4.1. Giá trị field `user` lưu trong `custom_data`
```json
{ "id": 12 }
```
- `id` = `users.id` (hệ thống này).
- Tên hiển thị: tra `users.full_name` theo `id`.
- ID hệ ngoài: tra `user_external_map(user_id, system)`.

### 4.2. DB

**Bảng mới `user_external_map`:**
```sql
CREATE TABLE IF NOT EXISTS user_external_map (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id INT NOT NULL,
  system VARCHAR(50) NOT NULL,
  external_id VARCHAR(100) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uq_user_system (user_id, system),
  UNIQUE KEY uq_system_external (system, external_id),
  KEY idx_user (user_id),
  CONSTRAINT fk_uem_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**Thêm cột `system_key` vào `api_configs`** (định danh hệ: `1office`, `crmB`...).

### 4.3. Mapping push/pull
- **Push** (đề xuất → 1Office): `users.id` → `user_external_map(system)` → gửi id vào `user_ids`/`manager_user_ids`.
- **Pull** (1Office → đề xuất): `field_raws` trả id → tra ngược `user_external_map` → lưu `{ "id": users.id }`.
- Hệ (`system`) lấy từ `api_configs.system_key`.

### 4.4. Hiển thị & click
- Component `UserField`: chip **tên** + click mở `RecordDetailPopup entity="users"`.
- **CTV:** chỉ hiện tên, ẩn click.
- Backend `mergeData` resolve `label` để frontend không phải gọi từng user.

### 4.5. Nơi cấu hình trên giao diện (3 chỗ tách biệt)

| # | Nơi | Việc | Trạng thái |
|---|---|---|---|
| 1 | `/admin/users` → mục "Liên kết hệ thống" | Gán ID hệ ngoài cho từng người (`user_external_map`) | Chưa có — Bước 3/6 |
| 2 | `/admin/fields` | Định nghĩa field type `user` + `source_config.systems` | Chưa có — Bước 2/6 |
| 3 | `/admin/api-configs` → FieldMappingPanel (kéo-thả) | Gán `source_field` (user) → `target_field` (`user_ids`/`manager_user_ids`) | Đã có kéo-thả |

**Quan trọng:** kéo-thả ở `/admin/api-configs` chỉ lưu **mối quan hệ** nguồn→đích, không lưu id. Quy đổi sang id ngoài xảy ra **lúc bấm Push** (`syncService` → tra `user_external_map` theo `api_configs.system_key`). Nếu user chưa được gán mapping → bỏ qua + cảnh báo (không gửi sai, không chặn cả đề xuất).

**Điều kiện để "tự nhận" id:**
1. Đích 1Office là **type `user`** (`user_ids`, `manager_user_ids`).
2. `api_configs.system_key = '1office'` (biết đang map hệ nào).
3. Mỗi người đã có bản ghi trong `user_external_map`.

**Hiện trạng:** field `user` và UI gán ID hệ ngoài chưa tồn tại; toàn bộ `users.external_id` đang NULL → nếu kéo mapping bây giờ sẽ gửi **id nội bộ** (sai). Cần làm Bước 1–6.

## 6. Rủi ro & lưu ý

1. **Token admin** cho API user khác token contact → cần cấu hình riêng.
2. **1Office GET mặc định trả tên** → bắt buộc dùng `field_raws` khi pull.

5. **User bị xóa** → FK ON DELETE CASCADE xóa mapping; field `{id}` trong custom_data thành "mồ côi" → UI hiển thị "(không tồn tại)".
