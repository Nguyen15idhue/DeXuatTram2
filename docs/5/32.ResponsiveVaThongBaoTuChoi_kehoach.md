## 12. Fix: desc bị lặp (desc trong desc)

**Triệu chứng:** sau vài lần push/pull, desc trên 1Office chứa lại desc cũ (lặp).

**Nguyên nhân:**
- Mapping `description → desc` (id 27) có `direction = both`.
- `desc` là **special target** (được render từ Desc Template khi push), nhưng ở chiều **pull** nó ghi `contact.desc` (text) vào cột `description` của đề xuất.
- Lần push sau, Desc Template render trường "Mô tả" = chính desc cũ → **desc lồng trong desc**.

**Khắc phục:**
- `syncService`: loại các **special target** (`desc`, `files`) khỏi cả `pushMappings` và `pullMappings` (`!fieldMapper.isSpecialTarget(target_field)`).
- DB: đặt mapping 27 `direction='push'`.
- Dọn dữ liệu: xóa `description` của các đề xuất bị nhiễm (bắt đầu bằng `📋 Thông tin cơ bản`) — 393, 394, 395, 436.

**Kiểm chứng:**
- Set `description = MARKER`, pull config 3 → `description` **giữ nguyên MARKER** (không bị ghi đè).
- Push lại 436 → desc gửi đi có **1** "Thông tin cơ bản", chứa marker đúng 1 lần; 1Office nhận đúng, không lặp.
- Đã dọn marker và push lại (1Office hết marker).

**Files:** `backend/src/services/syncService.js`, DB `api_field_mappings`. Lưu ý: `desc`/`files` là special target — **không** cấu hình pull.
