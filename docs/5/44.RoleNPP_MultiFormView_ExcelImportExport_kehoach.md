## 3. Thiết kế

### 3.1. Metadata mới cho form/view (migration 78)

```sql
ALTER TABLE views ADD COLUMN usage VARCHAR(30) NOT NULL DEFAULT 'table';  -- table | excel_full | excel_basic
ALTER TABLE views ADD COLUMN is_locked TINYINT(1) NOT NULL DEFAULT 0;
ALTER TABLE forms ADD COLUMN is_locked TINYINT(1) NOT NULL DEFAULT 0;
ALTER TABLE forms ADD COLUMN is_default TINYINT(1) NOT NULL DEFAULT 0;
```

| Cột | Ý nghĩa |
|---|---|
| `views.usage` | View dùng ở đâu: `table` (bảng danh sách) / `excel_full` (template+import/export đầy đủ) / `excel_basic` (bộ cơ bản) |
| `views.is_locked` / `forms.is_locked` | `1` = **không cho xóa** (vẫn cho sửa nội dung + đổi `status`); BE `remove()` trả 400, FE ẩn/disable nút Xóa |
| `forms.is_default` | Form mặc định khi resolve theo `purpose` (có nhiều form cùng purpose) |

**Dữ liệu seed**:
- 3 view hiện tại (6 stations, 7 users, 8 proposals) → `usage='table'`, `is_locked=1`
- 6 form hiện tại (10,12,13,14,15,16) → `is_locked=1`
- Form `create` hiện tại (12 stations, 13 proposals, 15 users) → `is_default=1`

### 3.2. Cấu trúc 9 view (3 entity × 3 loại)

| stations | View Stations (6) | Excel Stations – đầy đủ | Excel Stations – cơ bản |

### 3.5. Nhận diện bộ cột khi import (tự động + xác nhận)

Hạ tầng đã có: `importPreviewDynamic` parse header file và dựng `buildHeaderMap` (so khớp **theo `label`**, không phân biệt hoa/thường) — `excelService.js:223-232`.

**Thuật toán**:
```
score(view)    = số cột của view CÓ MẶT trong header file
coverage(view) = score / số cột của view
fileExtra      = cột trong file KHÔNG thuộc view (sẽ bị bỏ qua)
missingView    = cột của view KHÔNG có trong file (sẽ để trống)

Ứng viên: view có entity khớp + usage IN ('excel_basic','excel_full') + status='active'
Chọn: score DESC → coverage DESC → ưu tiên excel_full
Ngưỡng: coverage < 0.5  ⇒ KHÔNG nhận diện, yêu cầu chọn thủ công
```

**Vì sao `score` (không phải "khớp đủ")**:

| File người dùng | view basic | view full | Chọn | Lý do |
|---|---|---|---|---|
| Đầy đủ (53 cột) | score 8 | **score 53** | `excel_full` | file đầy đủ **cũng khớp** mọi cột của basic → nếu chỉ so "khớp đủ" sẽ chọn nhầm basic ⇒ **mất 45 trường âm thầm** |
| Cơ bản (8 cột) | **score 8, cov 1.0** | score 8, cov 0.15 | `excel_basic` | hoà score → tie-break bằng coverage |

**Response `importPreviewDynamic` trả thêm**: `detectedViewId`, `detectedUsage`, `score`, `coverage`, `unmatchedFileColumns[]` (cột file không thuộc bộ → bị bỏ qua), `missingViewColumns[]` (cột bộ không có trong file → để trống), `omittedFields[]` (từ P5).

**UX 3 bước (không bắt chọn tay trước)**:
```
[1] Chọn file (KHÔNG cần chọn bộ cột trước)
      ↓
[2] Hiện kết quả nhận diện + cho override:
    ✓ Nhận diện: "Excel Proposals – cơ bản"  (khớp 8/8 cột)
      Cột trong file không thuộc bộ này: 0
      Sẽ để trống: 45 trường (6 bắt buộc)
    [Bộ cột: ▼ Excel Proposals – cơ bản]   ← luôn đổi được
      ↓
[3] "Xem trước" → lỗi theo dòng → "Import"
```

**Cảnh báo bắt buộc**:
* `unmatchedFileColumns.length > 0` → vàng: *"N cột trong file sẽ bị bỏ qua"* (kèm tên cột).
* Không nhận diện được (cov < 0.5) → đỏ: *"Không nhận diện được bộ cột — chọn thủ công"* + liệt kê cột lạ.
* Nhiều view cùng score & coverage → hiện danh sách để user chọn.

**Không auto 100%**: bỏ bước xác nhận ⇒ ca "file đầy đủ ↔ bộ cơ bản" có thể mất dữ liệu mà vẫn báo import thành công.
