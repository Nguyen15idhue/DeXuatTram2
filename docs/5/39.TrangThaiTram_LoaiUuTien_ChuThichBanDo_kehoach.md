## 8. Hành vi khi cập nhật lên VPS

Khi chạy `update.sh` → tự động `scripts/migrate.sh run`; chỉ file chưa có trong `schema_migrations` mới chạy (VPS sẽ chạy **70, 72** — lưu ý `71` thuộc kế hoạch 40).

| Đối tượng | Hành vi | Cơ chế |
|---|---|---|
| `stations.status` enum | Thêm `PLANNING`,`REJECTED` | `ALTER TABLE ... MODIFY` (guard information_schema) |
| Options field `status` | Thay thế 4 mục | `UPDATE field_definitions SET options=...` |
| Field `mo_hinh_tram`, `loai_uu_tien` | `INSERT` (bỏ qua nếu đã có) | `INSERT ... WHERE NOT EXISTS` |
| Form 10/12, view 6 | Thêm field/row | `INSERT ... WHERE NOT EXISTS` + cập nhật `layout_config` |
| `loai_uu_tien` dữ liệu trạm cũ | Tính lại | `recompute-stations.js` chạy tay (không auto) |

**Lưu ý bắt buộc khi lên VPS**
1. Tham chiếu field theo `(entity, key)` bằng subquery, **không hardcode `field_id`** (id VPS khác local).
2. Chạy tay `recompute-stations.js`: `docker cp` vào container rồi `docker exec station-backend node /app/scripts/recompute-stations.js`.
3. Enum đổi bằng guard `information_schema` (MySQL 8 không có `IF NOT EXISTS` cho enum).
