## 2. Phase 0 — Kết quả spike test 1Office ✅ HOÀN THÀNH (10/09/2026)

### Giới hạn file
- Số file tối đa / request: **≥ 10 file** (đã test 6 và 10 file, đều thành công). Không cần chia lô 5 như trước.
- `contact/update` **APPEND** file: insert 2 file → `files` = 2; update thêm 3 file → `files` = 5.
- Field thật lưu file trên 1Office là `files` (array); `num_file` luôn = 0 (không dùng).
- Format gửi: field `files` = JSON string `[{name, file: base64}]` trong body form-urlencoded của `contact/insert` / `contact/update`.

### Bằng chứng (script: `test_files/1office/spike29.cjs`)
| Bước | Kết quả | files trong contact |
|------|---------|---------------------|
| insert 6 file | 200, success | array(6) |
| insert 10 file | 200, success | array(10) |
| insert 2 file | 200, success | array(2) |
| update thêm 3 file | 200, success | array(5) → **append** |
| cleanup 3 contact test | 200 | đã xóa sạch |

### Kết luận chiến lược >5 file
- **Gửi tất cả file trong 1 request** khi insert (không cần batch).
- Vì `update` append → khi push lại proposal đã link, **chỉ gửi file MỚI** (chưa có trong snapshot `last_synced_data`) để tránh trùng file.
- Không cần dùng endpoint `/upload-file` riêng.

### Ghi chú
- Đã dọn sạch 3 contact test (`TEST_SPIKE29_*`).
- Giới hạn cứng thực tế của 1Office chưa chạm tới ở 10 file; đề xuất an toàn vẫn có thể thêm cảnh báo nếu proposal > 20 file.
