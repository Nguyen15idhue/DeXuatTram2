# 27. Tích hợp API 1Office — Kế hoạch tổng hợp

## 1. Tổng quan

### Mục đích
Tích hợp API 1Office (CRM bên thứ 3) với hệ thống quản lý trạm sạc hiện tại, cho phép đồng bộ dữ liệu đề xuất (proposals) sang hệ thống liên hệ1Office và ngược lại.

### Phạm vi
- Trang cấu hình API (mở rộng cho nhiều API trong tương lai)
- Ánh xạ trường dữ liệu (15 field types)
- Hàng đợi xử lý đồng bộ (queue system)
- Đồng bộ 2 chiều: Push (Proposal →1Office) và Pull (1Office → Proposal)
- Liên kết proposal với contact1Office
- Audit log theo dõi tất cả hoạt động

### API hiện tại
- **Base URL:** `https://egr.1office.vn`
- **Authentication:** Access token (query param)
- **Content-Type:** `application/x-www-form-urlencoded` (KHÔNG phải JSON)
- **5 API endpoints:** GET list, GET detail, POST insert, POST update, POST delete

### 5.1 Bảng tổng hợp

### 7.3 Queue Worker

```javascript
// queueWorker.js
class QueueWorker {
  constructor() {
    this.isProcessing = false;
    this.pollInterval = 2000;  // 2 giây
  }

  start() {
    setInterval(() => this.poll(), this.pollInterval);
  }

  async poll() {
    if (this.isProcessing) return;

    const job = await queueService.getNextPending();
    if (!job) return;

    this.isProcessing = true;
    try {
      await this.processJob(job);
    } finally {
      this.isProcessing = false;
    }
  }

  async processJob(job) {
    await queueService.updateStatus(job.id, 'processing');

    try {
      // Delay 1.5s giữa mỗi request (rate limit)
      await sleep(1500);

      let result;
      switch (job.action) {
        case 'push':
          result = await syncService.pushTo1Office(job);
          break;
        case 'pull':
          result = await syncService.pullFrom1Office(job);
          break;
        case 'sync':
          result = await syncService.syncBidirectional(job);
          break;
      }

      await queueService.updateStatus(job.id, 'completed', result);
    } catch (error) {
      if (job.retry_count < job.max_retries) {
        await queueService.retry(job.id);
      } else {
        await queueService.updateStatus(job.id, 'failed', { error: error.message });
      }
    }
  }
}
```

## 9. Queue System Design

### 9.1 Architecture

```
┌─────────────────────────────────────────────────────┐
│               In-Memory Queue                        │
│  pending: []     Chờ xử lý                          │
│  processing: null  Đang xử lý (serial)              │
│  completed: []   Hoàn thành                         │
│  failed: []      Thất bại                           │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────┐
│               Queue Worker                           │
│  setInterval 2s → lấy 1 job pending                 │
│  → delay 1.5s → gọi API1Office                      │
│  → update status → log vào MySQL                    │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────┐
│               MySQL Persistence                      │
│  api_queue_logs: status, request, response, error   │
│  Survive restart: re-queue pending jobs              │
└─────────────────────────────────────────────────────┘
```

### 9.2 Job States

```
pending → processing → completed
                  ↓
                failed → retry (≤3) → failed (final)
                  ↓
              cancelled
```

### 9.3 Rate Limiting Strategy

```javascript
// Config từ api_configs
{
  rate_limit_per_second: 5,
  rate_limit_per_minute: 60,
  request_timeout: 30000
}

// Implementation
- Delay 1.5s giữa mỗi API call (đã test verify)
- Nếu rate limit error → exponential backoff: 2s, 4s, 8s
- Max concurrent jobs: 1 (serial processing)
- Timeout: 30s per request
```

### 9.4 Retry Logic

```
Attempt 1: Gọi API
  → Success? → Done
  → Rate limit? → Wait 2s, retry
  → Error? → Wait 1s, retry

Attempt 2: Gọi API
  → Success? → Done
  → Rate limit? → Wait 4s, retry
  → Error? → Wait 2s, retry

Attempt 3: Gọi API
  → Success? → Done
  → Any fail? → Mark FAILED, log error
```

```
1. Kiểm tra proposal đã link chưa?
   ├── Có link → KHÔNG cho push, chỉ cho sync
   └── Chưa link → Tiếp tục

2. Map data theo field_mappings
   ├── proposal.name → contact.name
   ├── proposal.address → contact.address
   └── ... (theo mapping config)

3. Validate dữ liệu
   ├── Required fields (code, name)
   ├── Format (email, phone, date)
   └── Nếu lỗi → Return error, không tạo queue

4. Tạo queue job "push"
   └── Status: pending

5. Queue Worker xử lý
   ├── Gọi POST /api/customer/contact/insert
   ├── Response: postId, code
   └── Lưu contact_1office_id vào proposal

6. Log kết quả vào api_queue_logs
```

### 10.2 Pull (1Office → Proposal)

```
1. Lấy danh sách contacts từ1Office
   └── GET /api/customer/contact/gets

2. Check đã sync chưa?
   ├── Có contact_1office_id → Cập nhật proposal
   └── Chưa có → Tạo proposal mới

3. Map data theo field_mappings (reverse)
   ├── contact.name → proposal.name
   ├── contact.address → proposal.address
   └── ...

4. Tạo queue job "pull"
   └── Status: pending

5. Queue Worker xử lý
   ├── Gọi API1Office
   ├── Map data
   └── Tạo/cập nhật proposal

6. Log kết quả
```

### 10.3 Link Proposal ↔ Contact

```
1. Chọn proposal
2. Tìm liên hệ1Office theo code hoặc name
3. Lưu contact_1office_id vào proposal
4. Cập nhật sync_status = 'synced'

Lưu ý:
- Khi đã link, KHÔNG cho push nữa
- Chỉ cho phép sync (2 chiều)
- unlink proposal → set contact_1office_id = NULL
```

## 15. Risk & Mitigation

| Risk | Impact | Mitigation |
|------|--------|------------|
| 1Office API thay đổi | Cao | Version API config, test connection regularly |
| Rate limit exceeded | Trung bình | Delay 1.5s, exponential backoff, max 1 concurrent job |
| File quá lớn (>10MB) | Thấp | Validate trước khi push, skip nếu quá size |
| Field mapping sai | Trung bình | Preview trước khi sync, validation rules |
| Queue stuck (worker crash) | Trung bình | Auto-requeue pending jobs on startup |
| Mất dữ liệu khi restart | Cao | MySQL persistence cho queue logs |
| 1Office trả lỗi 500 | Trung bình | Retry 3 lần, alert admin |
