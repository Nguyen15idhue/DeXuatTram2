# PHASE 1 — Sửa lỗi tồn đọng trước cải tổ

> Từ review `/map` + `/admin/map-config`. **Bắt buộc xong trước** khi mở rộng `layers_config` công khai.

## Bước 1.1 — Bảo mật (C1, C2, C3)

**Nội dung cần thực hiện:**
1. **C1 — Không để API key trong `tile_url` công khai:** khi `tile_mode='proxy'`, lưu `tile_url` **không chứa key** (lưu template/`{key}` hoặc URL provider sạch); backend public `GET /map-configs` **strip key khỏi `tile_url`** (không chỉ cột `api_key`).
2. **C2 — Popup đường trùng lặp không chèn HTML thô:** dựng DOM + `textContent` (như popup marker) thay vì template string `${dupLabelOf(...)}`.
3. **C3 — Allow-list cột khi update config:** `mapConfigService.updateConfig` chỉ nhận danh sách cột hợp lệ (allow-list), không build `SET` từ key tùy ý.

**Yêu cầu cần đạt:**
- Public (không token) không trả key, kể cả provider có key (Geoapify/Mapbox), ở mọi `tile_mode`.
- Popup duplicate hiển thị đúng text, không thực thi HTML/script từ dữ liệu.
- `PUT /map-configs/:id` bỏ qua/từ chối cột không hợp lệ.

**Checklist test:**
- [ ] Chọn Geoapify + key, lưu `tile_mode='proxy'` → `GET /api/map-configs` không chứa key (grep).
- [ ] Chọn `direct` → key chỉ lộ khi thật sự cần (ghi chú/ cảnh báo).
- [ ] Tạo proposal có `code` chứa `<img src=x onerror=...>` → popup duplicate hiển thị text, không chạy script.
- [ ] PUT body có cột lạ (`foo='bar'`) → không ghi vào DB / bị chặn.
- [ ] `test-map.cjs`, `test-regression.cjs` PASS.

**Ghi chú:** C1 là điều kiện tiên quyết trước khi expose style/layers công khai. `direct` về bản chất lộ key ở client → phải giới hạn key theo HTTP referrer.

## Bước 1.2 — Hợp nhất catalog FE/BE + capability (H4, H5, M6)

**Nội dung cần thực hiện:**
1. **Một nguồn catalog**: backend `GET /api/map-configs/tile-providers` là **nguồn chuẩn**; FE lấy danh sách provider từ API (thay vì `utils/tileProviders.js` hardcode) — hoặc sinh FE từ cùng 1 file dữ liệu.
2. Thêm **capability** mỗi provider: `raster | vector | terrain`, `supports_retina`, `incompatible_with_leaflet`, `requires_key` — dùng để validate renderer/mode (Phase 6/7).
3. Sửa **H4**: `maplibre-self-hosted` (và mọi provider không dùng được Leaflet) có `incompatible_with_leaflet: true`.
4. Đồng bộ **H5**: `arcgis-js` `requires_key`; bổ sung `tile_url_styles`/`tile_url_template` cho mapbox/here/tomtom ở BE; thống nhất name/attribution.

**Yêu cầu cần đạt:**
- FE và BE không lệch (so khớp tự động).
- Provider list hiển thị đúng; provider không tương thích Leaflet không chọn được cho renderer Leaflet.
- Mỗi provider có `capabilities`.

**Checklist test:**
- [ ] Script so sánh catalog FE vs BE → không lệch.
- [ ] `GET /tile-providers` là nguồn FE dùng (không còn import hardcode).
- [ ] `maplibre-self-hosted` bị đánh dấu không tương thích Leaflet.
- [ ] Chọn từng provider khả dụng → không lỗi.

**Ghi chú:** quyết định "nguồn chuẩn" cần chốt (BE endpoint được khuyến nghị vì proxy cũng dùng chung).

## Bước 1.3 — Proxy / style / test / preview / khôi phục style (H1, H2, H3, H6)

**Nội dung cần thực hiện:**
1. **H1 — Style switch hoạt động ở proxy:** proxy nhận style (query `?style=`) hoặc đọc đúng style; `buildTileConfig` ở proxy phải phản ánh style đang chọn (không luôn `/tiles/{z}/{x}/{y}`).
2. **H2 — Test/Preview phản ánh đúng chế độ:** khi `tile_mode='proxy'`, test kết nối và preview đi **qua proxy** (`/tiles/...`) để đúng với production; có tùy chọn test direct cho chẩn đoán.
3. **H3 — Proxy báo lỗi rõ:** thay PNG trong suốt 200 bằng tín hiệu lỗi (ví dụ trả 204/redirect sang tile lỗi, hoặc header `X-Tile-Proxy-Status: fallback`) để FE hiện banner thay vì trắng im lặng.
4. **H6 — Khôi phục style đã lưu đầy đủ:** hỗ trợ cả `tile_url_styles` và `style_options`; effect cập nhật theo `style_url`; bỏ nhánh return sớm sai.

**Yêu cầu cần đạt:**
- Đổi style trên `/map` (nút layer) → tile đổi khi đang proxy.
- Test/Preview admin phản ánh đúng cái production dùng.
- Tile lỗi thật → banner cảnh báo (không im lặng).
- Mở lại map → dùng đúng style đã lưu.

**Checklist test:**
- [ ] `tile_mode=proxy`, đổi style `osm-de ↔ osm-fr` → tile đổi (kiểm qua `/tiles`).
- [ ] Admin Test kết nối khi proxy → test qua proxy; báo đúng.
- [ ] Chặn 1 nguồn → banner cảnh báo hiện.
- [ ] Lưu style → reload → map dùng đúng style.
- [ ] `test-map.cjs` PASS.

**Ghi chú:** cần thống nhất cách truyền style vào proxy (query param vs DB) — ảnh hưởng cache 30s.

## Bước 1.4 — Dọn dẹp & tăng độ bền (M3, M4, M5, L*)

**Nội dung cần thực hiện:**
1. **M3**: thêm `key` cho `TileLayer` ở `LocationMapModal` và mini map `MyProposalsPage` (tránh stale subdomains/url).
2. **M4**: bỏ fallback dùng `tile.openstreetmap.org` (bị chặn) trong MapView/Admin; fallback dùng mirror OSM/Esri.
3. **M5**: dọn whitelist proxy (bỏ host CARTO đã gỡ), thống nhất `maxZoom`, chỉ áp `@2x` khi `supports_retina`; ghi chú cache 30s.
4. **M7**: bỏ/gộp `style_value` (dùng `style_url`) để hết nhiễu.
5. **Low**: `MapPage` bỏ remount kép (`key` + `refreshKey`); `ProvinceBoundaryLayer` abort fetch; gộp helper `isValidTileUrl/resolveTileUrl`.

**Yêu cầu cần đạt:**
- Secondary maps đổi provider/style đúng; không còn tham chiếu host bị chặn ở fallback.
- Không còn dead code gây nhiễu.

**Checklist test:**
- [ ] Đổi provider → LocationMapModal + mini map đổi theo.
- [ ] Không còn `tile.openstreetmap.org` trong fallback (grep).
- [ ] Grep `style_value` không còn dùng.
- [ ] `test-regression.cjs` 6 trang PASS.

**Ghi chú:** các mục Low có thể gộp nếu không ảnh hưởng.
