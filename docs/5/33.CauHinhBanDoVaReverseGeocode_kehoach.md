## 1. Bối cảnh & mục tiêu

### Yêu cầu 1 — Cấu hình bản đồ phải thực sự có tác dụng
Admin "Map Config" hiện lưu được vào DB nhưng **không thay đổi bản đồ đang chạy**; tile OpenStreetMap bị chặn (`x-blocked: Access denied`) → map trắng. Cần:
1. Cấu hình trong admin phải **áp dụng thật** lên mọi mặt bản đồ.
2. Cho phép chọn provider **không phụ thuộc Leaflet** (Google Maps, và các provider raster/vector khác).
3. Có phương án chống chặn tile (Geoapify) + fallback rõ ràng, không im lặng.

### Yêu cầu 2 — Tự phân giải địa chỉ từ tọa độ
Khi form có `latitude`/`longitude`, tự reverse geocode → tự điền **`address`**, **tỉnh/thành (`province`/`ma_tinh`/`vung_mien`)**, **phường/xã (`xa_phuong`)** nếu các ô này đang trống.

### Phạm vi đã chốt
| # | Hạng mục | Quyết định |
|---|---|---|
| 1 | Phạm vi map đợt này | **Vá luồng tile trước**, giữ Leaflet, dựng sẵn "seam" renderer để sau cắm Google/MapLibre |
| 2 | Provider | Dùng **Geoapify** (tile raster + reverse geocode, cùng 1 key) |
| 3 | Cơ chế geocode | **Cả frontend** (hiện ngay khi nhập/chọn tọa độ) **lẫn backend** (đảm bảo dữ liệu, phủ Excel/sync) |
| 4 | Địa giới hành chính | Data List đã cập nhật **2 cấp** (KHÔNG cần chuyển đổi dữ liệu cũ) |
| 5 | Cơ chế ẩn key | Mặc định `tile_mode = proxy` (server giữ key); tùy chọn `direct` (client giữ key, giới hạn theo referrer) |
| 6 | Tự điền | Chỉ điền ô **đang trống**, KHÔNG ghi đè dữ liệu người dùng đã nhập |

### 2.3. Spec Geoapify (đã xác minh)
- **Raster tile:** `https://maps.geoapify.com/v1/tile/{style}/{z}/{x}/{y}.png?apiKey={key}` (thêm `@2x` cho retina). Style: `osm-carto`, `osm-bright`, `osm-bright-grey`, `positron`, `dark-matter`, `toner`, `klokantech-basic`... maxZoom 20.
- **Reverse geocode:** `https://api.geoapify.com/v1/geocode/reverse?lat=..&lon=..&format=json&lang=vi&apiKey=..` → `formatted`, `address_line1/2`, `city`, `county`, `state`, `suburb`, `district`, `street`, `housenumber`, `postcode`, `result_type`, `rank.confidence`.
- **Free plan:** 3000 credit/ngày; tile 0.25 credit/lượt; geocode 1 credit/lượt. Bắt buộc attribution **Geoapify + OSM + OpenMapTiles**. Key giới hạn được theo HTTP referrer/origin.

### 3.1. Database (migration tiến tới, idempotent, KHÔNG DROP)

### 3.2. Luồng tile (sau khi sửa)
```
Admin lưu map_configs (provider=geoapify, style, key, tile_mode, retina, renderer)
   ↓
MapView fetch GET /api/map-configs (safe) → chọn renderer + tile URL
   ├─ tile_mode='proxy'  → /tiles/{z}/{x}/{y}?entity= → backend đọc DB, build URL có key (key ẩn)
   └─ tile_mode='direct' → browser gọi thẳng provider (key client-side, giới hạn referrer)
   ↓
Lỗi tile thật → đổi sang fallback (Esri/OSM direct) 1 lần → nếu vẫn lỗi: cảnh báo 1 lần
```

### 3.3. Luồng reverse geocode
```
Người dùng nhập/chọn lat-lng (form hoặc click map)
   ├─ FE: DynamicForm watcher (debounce 700ms) → POST /api/geocode/reverse → điền address/province/xa_phuong (ô trống)
   └─ BE: các service ghi → geocodeService.reverse (cache) → điền ô trống → applyDiaGioi (suy ma_tinh/vung_mien)
```

### 3.4. Renderer seam (kiến trúc mở)
- Thư mục mới `frontend/src/components/map/renderers/`
  - `index.js`: `getRenderer(rendererId)` trả renderer hoặc null.
  - `leafletRenderer.js`: cài đặt interface hiện tại bằng Leaflet.
  - `INTERFACE.md` (hoặc comment JSDoc): `{ mount, setView, setTileLayer, addMarkers, addPolylines, on(event, cb), destroy }`.
- `MapView` đọc `config.renderer`; chưa hỗ trợ (vd `google`) → cảnh báo + fallback Leaflet. **Không** build Google renderer trong đợt này.

### Bước 4 — Proxy `/tiles` đọc cấu hình + hỗ trợ Geoapify + retina

**Nội dung:** Cho `tiles.js` build tile URL từ `map_configs` (provider/style/key server-side) thay vì hardcode OSM; mở rộng whitelist; hỗ trợ retina; vẫn cache.

**Yêu cầu cần đạt:**
- `GET /tiles/{z}/{x}/{y}?entity=stations` trả tile của provider đã cấu hình, key ẩn phía server.
- Chỉ cho phép host thuộc whitelist (Geoapify, OSM, Esri, OpenTopo, self-host cấu hình).
- Retina: `/tiles/{z}/{x}/{y}?entity=stations&r=2x` → tile `@2x`.
- Lỗi mạng vẫn trả fallback nhưng có log rõ ràng.

**Chi tiết thực hiện:**
1. Thêm helper đọc `map_configs` theo `entity` (cache ngắn 30–60s trong memory) → lấy provider/style/key/retina.
2. Build URL từ provider catalog backend (dùng chung hàm với Bước 2).
3. Mở rộng `ALLOWED_TILE_HOSTS` thêm `maps.geoapify.com`; giữ nguyên tắc chặn host lạ.
4. Parse query `entity`, `r` (retina).
5. Log lỗi tile (`console.warn('[TileProxy] ...')`) + vẫn `sendFallback` để UI không vỡ.
6. Nếu cấu hình trỏ provider có `{domain}`/self-host → yêu cầu tile URL cụ thể (đã có ở admin).

### Bước 13 — Frontend: watcher tự điền trong DynamicForm

## 5. Rủi ro & lưu ý

1. **Key lộ khi `tile_mode='direct'`**: bản chất direct; phải giới hạn key theo HTTP referrer/origin trên Geoapify. Khuyến nghị `proxy` để ẩn key.
2. **Chi phí Geoapify**: free 3000 credit/ngày; tile 0.25/geocode 1 credit. Cache + debounce + chỉ điền ô trống là bắt buộc để tiết kiệm. Cân nhắc gate geocode theo env khi import hàng loạt.
3. **Proxy tốn băng thông server**: `direct` nhẹ server hơn nhưng lộ key — chọn theo ưu tiên.
4. **Khớp địa giới**: tên Geoapify có thể lệch Data List 2 cấp → chỉ điền khi khớp; cần bộ tọa độ test đại diện. KHÔNG ghi giá trị ngoài option của select.
5. **Attribution bắt buộc**: hiển thị đủ Geoapify + OSM + OpenMapTiles ở mọi mặt map dùng tile Geoapify.
6. **Không hồi quy**: marker/popup/filter/duplicate lines/location modal phải giữ nguyên hành vi.
7. **Migration an toàn**: chỉ tiến tới, idempotent, KHÔNG DROP; baseline DB mới dựng bằng dump chuẩn + `mark-all`.
8. **Docker volume**: không xóa source volumes; thêm package (nếu có) cần rebuild.
9. **Catalog FE/BE trùng**: chấp nhận tạm, nhưng phải giữ khớp; nếu lệch gây bug tile.
